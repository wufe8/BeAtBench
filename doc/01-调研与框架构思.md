## 1. 定位与目标

**一句话定位**：面向 BMS（Be-Music Source）谱师的**新一代开源跨平台谱面编辑器**，
替代 Windows 时代的 BMSE / iBMSC 谱系，把 osu!lazer、Phira、Sonolus 这一代编辑器的体验带给 BMS 社区。

核心目标：

1. **现代编辑体验**：波形对齐、内置试玩、拖拽/键盘双输入、深色主题、HiDPI。
2. **格式原生**：BMS 文本（.bms/.bme/.bml/.pms）与 **bmson**（BMS 的 JSON 交换格式）一等公民，往返无损。
3. **正确性优先**：时序引擎（BPM/STOP/节拍通道）经得起变速谱考验，双向换算 + 谱面检查。
4. **谱师工作流闭环**：采样管理 → 摆键 → 变速 → 试玩 → 检查 → 打包发布，全在编辑器内完成。
5. **工程现代化**：模块化、可测试、git 友好（bmson 原生可 diff），GPL-3.0 合规选库。

**结论**：旧编辑器（BMSE/iBMSC）是 VB 时代的 Windows 遗产，痛点集中在——无波形、无内置试玩（试玩要另开 LR2/beatoraja）、UI 陈旧、跨平台无望。
现代尝试中 BmsTWO（C++/bmson）是唯一活跃者，但生态覆盖（BMS 文本兼容、试玩、lint、发布打包）仍是空白。**新编辑器的机会窗口真实存在**。

### 2.2 其他音游的谱面与编辑器（可借鉴点）

| 游戏/工具 | 谱面格式 | 编辑器亮点 | 借鉴 |
|---|---|---|---|
| osu!（[ppy/osu](https://github.com/ppy/osu) lazer） | .osu 文本：TimingPoints(BPM/offset/SV) + HitObjects(绝对 ms) | 波形定位、**BPM 测量向导（打拍定 BPM）**、snap 细分、即时保存、[编辑器架构](https://deepwiki.com/ppy/osu/4.3.1-editor-core-and-screens)（EditorClock/Beatmap 分层） | 时间轴 UI、测 BPM 向导、试玩即编辑 |
| StepMania/Etterna（.sm/.ssc） | 文本：每行=1/4 拍位、BPM/STOP/DELAY/WARP | 网格+量化、单文件多难度(#NOTES 段) | 与 BMS 同为「拍位+小节」流派，量化/网格思路直接对应；.ssc 单文件多难度的项目模型参考 |
| [Quaver](https://github.com/Quaver/Quaver)（C# + MonoGame，MPL-2.0） | .qua 自研文本，时间 ms | 游戏与编辑器同进程，即时试玩 | 编辑器内置引擎的收益验证 |
| ADOFAI | .adofai JSON | 角度/轨道可视化 | JSON 谱面可 diff |
| [Phira](https://github.com/TeamFlos/phira)（**Rust**，GPL-3.0）+ [phichain](https://github.com/Ivan-1F/phichain)（Rust，LGPL-3.0） | Phigros 谱面 JSON | **Rust 写编辑器 + 内置试玩**的可行性证明 | 技术路线参照物 |
| [Sonolus](https://github.com/Sonolus)（TypeScript 核心 MIT） | 引擎无关 JSON，秒为单位 | 网页端编辑、引擎/皮肤解耦 | 核心模型与渲染解耦的思想 |

**格式设计流派小结**（决定我们的内部模型）：

1. **绝对时间流**（osu!/Quaver）：note 携带 ms 时间。好处是直觉；坏处是变速后整体重算、难 diff。
2. **拍位+小节流**（BMS/StepMania）：note 携带 (小节, 节内位置)，BPM/STOP 是独立事件。BMS 天生如此，**必须保持**。
3. **JSON 事件流**（bmson/ADOFAI/Sonolus）：结构化、可 diff、可扩展。

→ **内部模型**：以「拍位+小节」为权威存储（事件型），时间(ms) 一律作为**派生缓存**由时序引擎计算；
bmson 因本身就是事件型 JSON，与内部模型近乎 1:1，作为**原生编辑格式**；BMS 文本作为兼容导入导出层。

## 3. 需求分析

### 3.1 谱师核心工作流（驱动功能域划分）

```
选曲/采样 → [BPM 测量/变速设计] → [铺底/摆键] → [长音与修饰] → [试玩校准] → [检查/打包]
     音频域          时序域            编辑域          编辑域           试玩域          交付域
```

### 3.2 功能需求清单

**A. 谱面 IO 与兼容**
- 读取/写出 BMS 文本：.bms/.bme/.bml/.pms，7key/5key/9key(PMS)、SP/DP、LNTYPE 1/2、地雷、RANDOM/IF/SWITCH 预处理。
- 读取/写出 bmson（原生编辑格式，另存 .json）。
- 编码检测与策略：Shift-JIS 传统 vs UTF-8（写入默认 UTF-8 + 可选 SJIS，兼容 `#ENCODING` 注释；读取自动检测）。
- 单文件多差分（#RANDOM 结构）解析与提示；zip 谱面包导入/导出。
- 往返保真：文本 → 模型 → 文本 的归一化写出（保留原始注释/风格可配置）。

**B. 元信息编辑**
- 全部头部字段表单化 + 常用组合（#TITLE 差分名自动识别、#ARTIST obj:/bga: 惯例提示）。
- 缺省值显式警告（#RANK/#TOTAL/#PLAYLEVEL/#DIFFICULTY 播放器默认值不统一）。

**C. 时间轴与导航**
- 小节/拍网格（1/4 ~ 1/192 细分），BPM 通道、STOP 通道、节拍通道（ch02）可视化。
- 双标尺：小节坐标 ↔ 秒坐标（变速后非线性映射的直观呈现）。
- 书签、节标记（section 标记）、小节跳转、迷你地图（全曲密度鸟瞰）。
- 缩放（横/纵）、惯性滚动、跟随播放。

**D. 音符编辑**
- 双输入：**键盘模拟 LR2 布局**（1P 7key+皿、DP 布局、PMS 9key 可配置）与鼠标点放/框选/拖动/滚动微调。
- 剪贴板：复制/剪切/粘贴（含跨小节、按时间或按拍位粘贴、重复粘贴 ×N）。
- 变换：镜像/旋转（LR2 式 mirror/random）、整体位移、量化(quantize)、按拍子放大缩小、密度缩放、和弦工具、随机化（可种子）。
- 多通道并排编辑（iBMSC 式每轨一栏），ch01 BGM 轨分栏显示以便对齐铺底。
- snap 细分 + 网格吸附 + 连打吸附（ghost note 预览）。

**E. 长音(LN)与地雷**
- LN 头尾配对可视化（跨小节高亮、颜色区分）、批量 LNTYPE 1↔2 转换、重叠/未闭合检测与一键修复。
- 地雷通道（D1-D9/E1-E9）、隐形音（WW/00 占位）、#LNOBJ 自定义终止符管理。

**F. 音频与波形**
- **波形显示**：BGM 全曲波形 + 按 keysound 分轨波形（峰值缓存、多级缩放）。
- **offset 校准**：波形上直接拖动对齐格线。
- 节拍器（细分可选）、击键音、单采样试听、采样替换/归一化。
- 采样管理器：去重、重命名、缺失扫描、36 进制 ID 上限（1296）占用视图。

**G. 变速与 BPM 工具**
- **打拍测 BPM**（参考 osu! timing wizard）+ 已知时长反推 BPM + offset 微调向导。
- BPM/STOP 事件编辑（拖拽、数值编辑、区间选择后统一 +/-），stop 时长可视化（画面停顿感预览）。
- 变速谱（SOF-LAN 系）专项：ch03 vs ch08 切换提示、负 BPM 警告。

**H. 试玩与预览**
- **内置简化试玩**：判定（PG/GR/GD/BD/PR）、自动播放、血条、流速调节、任意位置起播、LN 判定可视化。
- 外部启动器集成：一键写入临时 BMS 并唤起 beatoraja/LR2 热重载预览（文件监控或快捷键重载）。
- BGA 预览（静态帧/时间轴缩略），BGI/BGA 图层与透明度/ARGB 滤镜的最小呈现。

**I. 检查与 lint**
- 规则集（详见 §5.7），按严重度分级，给出定位与一键修复建议，导出检查报告。

**J. 项目管理与发布**
- 谱面 = 文件夹项目（BMS 文件 + wav/ogg + 图片 + 预览文件），`项目文件` 记录编辑器状态（采样映射、书签、UI 布局）但不污染谱面文件。
- 发布：一键生成 zip 包（标准目录结构）、`#PATH_WAV` 清理提示、文件引用完整性检查、缺失 #STAGEFILE/#BANNER 提示。

**K. 体验与扩展**
- 无限制 undo/redo（合并连续拖动）、自动保存（崩溃恢复）、可配置快捷键/主题/皮肤、中英日三语 i18n、键盘输入法冲突规避（编辑态切换 IME）。
- 留出插件/脚本接口（后期：Lua/自定义 lint 规则）。

### 3.3 v1 非目标

联机协作、AI 自动生成谱面、完整 BGA 视频编辑、内置完整游戏引擎（判定精度追求"够试玩"而非"比赛级"）、移动端。

## 4. 技术选型

### 4.1 推荐方案 A：**Rust + egui**（主推）

**理由**：

1. **Phira/phichain 已验证**：Rust 社区已有 GPL-3.0 音游编辑器先例（Rust + egui + wgpu）。
2. **音频是刚需**：Rust 的 cpal/kira/symphonia 生态成熟、跨平台、低延迟可控（谱面编辑器对音频时序要求远高于普通应用）。
3. **单二进制分发**：无运行时依赖，Windows/macOS/Linux 通吃，对老 BMS 玩家（Windows 用户）零门槛。
4. **性能**：变速谱时域计算、波形绘制、数万音符渲染都吃得下；egui 即时模式对编辑器类 UI 很合适。
5. **长期可扩展**：核心 crate 纯逻辑无 UI 依赖 → 未来编译到 wasm（egui/eframe 原生支持 Web 后端）可以出网页版。
6. **GPL-3.0 选库自由**：周边库几乎全是 MIT/Apache/MPL-2.0，无许可冲突（详见 §4.3）。

**代价**：Rust 学习曲线、egui 无成熟 Dock 生态（需少量自研面板管理）、CJK 字体需自行嵌入。

### 4.2 备选方案对比

| 方案 | 栈 | 优点 | 缺点 | 何时选它 |
|---|---|---|---|---|
| A | Rust + egui/eframe | 见上 | 生态较年轻 | **默认** |
| B | Tauri + TypeScript/Web（React/Solid + Web Audio + 自绘 Canvas/WaveSurfer） | Web 技术栈门槛低、UI 迭代快、Sonolus 先例 | 音频精确调度与文件系统是短板；Web 无沙箱逃逸时发布链更长 | 团队以 Web 开发为主；且可接受 Tauri 内用 Rust 补音频引擎 |
| C | C# + osu.Framework（.NET 8） | osu!lazer 编辑器全套框架现成、battle-tested | 生态绑定 osu!、社区对非 osu 用途支持有限；分发体积大 | 团队熟 C# |
| D | C++ + Dear ImGui（BmsTWO 谱系） | 与活跃项目 BmsTWO 同谱系，可互相参考/复用 | 开发效率最低、内存安全与依赖管理成本高 | 想直接 fork/共研 BmsTWO |

**决策标准**：单人/小团队 + 重音频 + 跨平台 + 长期维护 → A；Web 前端经验 > 音频经验 → B。

## 5. 架构设计

> ⚠️ 本章节为选型阶段的原始架构设想（当时考虑 Rust）。最终选用 **C++20 + Qt Quick/QML**，
> 实际目录结构与类型表示已更新；音频/MIDI/bmson 等模块尚未实现（见 doc/02 §7 里程碑规划）。

### 5.2 核心数据模型（权威存储 = 事件流）

```
Chart {
  meta:           std::map<std::string, std::string>   // #TITLE/#ARTIST/... 结构化 + 未知字段透传
  bpm_events:     std::vector<Event<Bpm>>              // 位置 + 值 + ch08标记 + ref_id
  stop_events:    std::vector<Event<Stop>>             // 位置 + 原始计数 n + ref_id
  measure_events: std::vector<Event<MeasureLen>>       // ch02 每小节拍数（四分拍）
  notes:          std::vector<Event<Note>>             // 位置 + Lane + sample引用 + LN配对 + bgm_line
  bga_events:     std::vector<Event<Bga>>              // 位置 + layer + image.id
  samples:        std::map<(SampleKind,id), SampleDef> // #WAVxx/#BMPxx/#BPMxx/#STOPxx 定义表
  raw_lines:      std::vector<std::string>             // 注释/控制指令/未知行（原样保留）
  mode_id:        std::optional<std::string>           // 游玩模式（sp7k/dp/battle/pms9k）
  id_base:        IdBase                              // 36进制/62进制
}
Event<T> { measure: uint32_t, pos: Rational /* 节内位置 0..1 有理数 */, value: T }
```

**要点**：
- **有理数**表达节内位置（BMS 槽位 = 字符串长度 N 的第 i 格 = i/N，天生有理数），避免浮点漂移破坏往返保真。
- 每条 note 的**时间(ms) 是派生值**，由 timing 引擎生成并随 BPM/STOP 编辑失效（脏标记 + 增量重算）。
- LN 在模型内表示为配对结构（头 note + 尾 note 双向引用 + 状态机），与 LNTYPE 1/2 的文本层表示解耦：**文本层适配格式，模型层统一语义**。
- RANDOM/IF/SWITCH：解析为「条件块」结构保留，编辑时以分支视图呈现；写回时重建。
- bmson ↔ 模型近乎直映射（事件型 JSON），BMS 文本 ↔ 模型靠布局推断（同一小节同一通道拆成多个 #NNNCC 行的合并/拆分策略）。

### 5.3 时序引擎（core/timing）

- **正算**（拍位→时间）：按 (小节, 节内位置) 排序构建分段线性函数：
  每小节时长 = 节拍值 × 4 × (60/BPM)，BPM 事件在该位置生效，STOP 作为时间轴上的跳变（间隙）。
  用「事件索引 + 前缀和 + 二分」实现 O(log n) 查询；缓存小节的绝对起始时间戳，脏区增量失效。
- **逆算**（时间→拍位）：STOP 间隙内的时间映射到 STOP 起点（试玩定位语义需明确定义：停在 STOP 前）。
- 数值域：BPM 可为 0/小数/负数（负数按规范宽容处理并警告）；STOP 值 n = n/192 个「触发该拍位 BPM 的
  全音符」（全音符 = 4 拍 = 240/BPM 秒，秒 = n×1.25/BPM；**不烘焙固定秒**）；节拍通道可为小数。
- 精度策略：内部用 i64 微秒或 f64 秒（拍位保留有理数），对外毫秒取整只在渲染层。
- **正确性锚点**：用 `Doppelganger[Eb]` 等真实变速谱做黄金测试；与 bms-rs / beatoraja 换算结果交叉验证。

### 5.4 IO 层

- **BMS 文本**：手写 tokenizer+parser（大小写不敏感、`//` `/* */` 注释、`#RANDOM/#IF/#SWITCH` 预处理）。
  写出采用「节内槽位最小化 + 通道按行聚合」的归一化策略，**保留原注释块与头部顺序**（风格保留开关）。
  ✅ 已实现（`core/src/bms/`）。
- **编码**：读取探测（BOM/Shift-JIS 启发式/`#ENCODING`）；写出默认 UTF-8，可选 SJIS。
  ✅ 已实现（`core/src/bms/encoding.cpp`）。
- **CodecRegistry**：格式注册表，新格式只需注册 Codec 实现。✅ 已实现（`core/src/codec/`）。
- **bmson**（⏳ 规划中）：JSON 严格 schema 校验，作为「保存工程」格式（git 友好）与社区交换格式。
- **zip**（⏳ 规划中）：发布打包与谱面包导入；导入时做文件引用重定位。

### 5.5 音频引擎（⏳ Phase B+ 规划，未实现）

- **输出**：独占/共享流；内部混音器按**音频回调时钟**调度（不是墙钟），消除漂移。
- **预览播放**：look-ahead 调度器——解码缓存按需预取，keysound 触发走精确采样位点；
  播放头时间来自已消费帧数，与 timing 引擎反查拍位。
- **波形**：每文件离线算峰值金字塔（多分辨率 min/max/RMS），LRU 缓存。
- **试玩判定**：简化判定窗口（可配置），目标是「谱师自检」而非竞技精度。
- **MIDI**：设备输入录制键位 → 按当前 snap 量化落 note（BMSE 经典功能）。

### 5.6 编辑模型与 undo/redo

- **Command 模式**：每个编辑操作实现 `apply/invert/merge`（连续拖动/滚轮微调合并为一个 undo 步）。
- 命令作用在 `Chart` 上，`Selection`/`Viewport`/`Playhead` 不入 undo 栈（会话状态）。
- 时间轴编辑与 BPM/STOP 编辑共用同一套命令栈 → 天然支持「改 BPM → 撤销」。
- 自动保存：文档快照 + 命令日志增量落盘（崩溃恢复 = 重放）。

### 5.7 检查器（lint）规则清单（v1）

*结构性*：LN 未闭合/自配对/跨 LNTYPE 混用；同一 tick 同通道叠音（非 01 轨）；通道误用（游玩轨道放 BGA 值等）；
节拍通道缺失小节；BPM=0 除零风险；负数 BPM 兼容警告；STOP 时长过大（>255/192s 时 #STOP 表示上限提示）。
*采样域*：引用未定义采样 / 定义未引用采样；超出 00-FF（256）或 00-ZZ（1296）上限（兼容性分级）；mp3 keysound 延迟警告（建议 ogg/wav）；同名不同后缀歧义。
*头部域*：#RANK/#TOTAL/#PLAYLEVEL/#DIFFICULTY 缺失或取值怪异；#LNOBJ 与 LNTYPE 冲突；#PATH_WAV 残留。
*编码/发布*：编码不一致；文件名大小写（zip 跨平台）；缺失 #STAGEFILE/#BANNER/#PREVIEW 提示级。
*玩法建议（提示级）*：密接押（同 tick 多键）统计、单手配置密度、LN 尾部判定敏感区间提示。
每条规则：`id / 级别(error|warning|info) / 定位 / 描述 / 修复建议(可选自动修复)`。

### 5.8 项目模型与发布

- 谱面文件夹即项目；`项目文件`（如 `.beatbench.json`，随项目文件夹存，**不写入 BMS 文件**）保存：采样映射、书签、视图布局、lint 抑制列表。
- 差分管理：同文件夹多差分文件 + 采样共享；差分间复制借用 note 块（跨文件剪贴板）。
- 发布向导：引用完整性 → 编码/规范 → zip 打包（标准目录结构）→ 可选自动打开 beatoraja 验证。
