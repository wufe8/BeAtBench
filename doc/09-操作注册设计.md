# BeAtBench UI 动作注册表设计（09）

> 状态：**设计稿 v1（2026-08 定稿要点）**。主题：**操作注册规范化**——把硬编码 UI 动作抽为「动作 id → 处理器」注册表，为皮肤系统（L2/L3）与扩展性铺路。
> 关联：`doc/08` §6（待办升级为本稿）、`doc/04`（M3 剩余 #1）、`doc/07` §3 5.6、`doc/05` §14.2；`doc/06`（命令协议/插件分层，本稿的 UI 侧镜像）。
> 图：`local/archify/beatbench-architecture-v3.html`（现状+规划并存）。

## 0. 决策（2026-08 拍板）

1. **UiActionRegistry 落在 app/bridge（C++ QObject）**，QML 只读消费 + 触发——与 `CommandDispatcher` / `ThemeManager` 同层，回补 doc/08 §2 双语言纪律（SessionController.qml 918 行业务逻辑逐步回抽 C++）；
2. **快捷键默认表代码内置**（注册表定义时声明，QML Shortcut 改查表生成）；`keymap.json`（含皮肤覆写）后置皮肤系统（M7+）；
3. **试点先行**：文件 / 编辑 / 视图 / 工具 四类高频动作先落地验证机制，其余动作进迁移清单分批替换；
4. **边界**：动作 = UI 意图；命令 = 文档变更。动作处理器可组合 0..N 条 core 命令 + 视图刷新；注册表**不重复造命令层**。

## 1. 动机与现状

- `Main.qml` 现有 **11 个硬编码 Shortcut**（Ctrl+O/S/Shift+S/Z/Y/C/V、Del、数字 1-5、Esc、Ctrl+Q），直接绑函数；
- `SessionController.qml`（918 行）约 **40 个动作函数**（`sessionCmd`/`dispatchCmd` + `placeNote`/`deleteSelection`/`quantizeSelection`/`transformSelection`/`saveChart`…）——动作定义、快捷键、启用条件全混在 QML JS 里；
- **L3 皮肤（重写 chrome，doc/08 §3）无法复用硬编码动作** → 皮肤壳必须按动作 id 触发；
- 与 core「命令即接口」（doc/06 §1）同构：`cmd::Registry`（数据面）↔ `UiActionRegistry`（UI 面）——插件/皮肤按 id 发现与触发。

## 2. 概念与边界

| 层 | 对象 | 状态 | 说明 |
|---|---|---|---|
| UI 动作 | `UiAction`（id + 元数据 + 处理器） | 规划（本稿） | 用户意图：`file.open`、`edit.undo`、`view.toggleGrid`、`tool.select` |
| 协议命令 | `cmd::Command`（无状态 JSON 信封） | 已落地 | 引擎能力唯一操作面（doc/06 §3） |
| 编辑命令 | `EditCommand`（有状态 apply/invert） | 已落地 | 文档变更原语，由协议命令包装 |

**关系**：`动作 → 处理器 → 0..N 条协议命令 dispatch + 视图刷新（chartSession.refresh()）`。

**反例（不要做）**：动作 = 命令的别名（重复造命令层）；处理器里写 UI 表现逻辑（表现留 QML）。

## 3. 动作 id 命名规范

- 点分命名空间，与 core 命令同构：`<域>.<动词>` 或 `<域>.<名词>.<动词>`；
- 域：`file` / `edit` / `view` / `tool` / `session` / `sample` / `bga` / `timing` / `help`；
- 示例（试点四类）：

| 域 | 动作 id | 说明 |
|---|---|---|
| file | `file.open` / `file.save` / `file.saveAs` / `file.close` | 打开/保存/另存为/关闭 |
| edit | `edit.undo` / `edit.redo` / `edit.copy` / `edit.paste` / `edit.delete` | 与协议命令 `session.undo` 等对齐 |
| view | `view.toggleGrid` / `view.toggleChannelIds` / `view.zoomIn` / `view.zoomOut` / `view.switchPage` | 视图状态（不入 undo 栈） |
| tool | `tool.select` / `tool.place` / `tool.ln` / `tool.mine` / `tool.pan` / `tool.quantize` / `tool.transform` | 工具选择 + 批量编辑 |

- **id 即契约**（皮肤/脚本依赖）：改名 = 版本化迁移；注册表可枚举（`ids()`），等效于 core 的 `capabilities`。

## 4. 动作元数据（UiActionDef）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定动作 id（§3 规范） |
| `label` | string | 人类可读名（`qsTr` 可翻译） |
| `shortcut` | string | 默认快捷键（如 `"Ctrl+S"`；空 = 无） |
| `enabled` | 谓词 | 启用条件（`canUndo` / `hasChart` / `currentPage` 等） |
| `checked` | 谓词? | 勾选态（网格/通道 id 等 toggle 动作） |
| `icon` | string? | 图标 id（L1 皮肤可换贴图；v1 可空） |
| `category` | string | 域（菜单分组依据，v1 一级菜单） |

## 5. C++ 接口（app/bridge/UiActionRegistry.hpp，新建）

```cpp
// app/bridge/UiActionRegistry.hpp（QObject，QML context property `UiActionRegistry`）
class UiActionRegistry : public QObject {
    Q_OBJECT
public:
    using Handler = std::function<bool(const QVariantMap& args)>;  // false = 动作失败（状态栏提示）

    void add(QStringView id, UiActionDef def, Handler handler);   // 重复 id 注册 = 断言/日志（守卫）
    const UiActionDef* find(QStringView id) const;
    QStringList ids() const;                                       // 可枚举（capabilities 式）

    // QML 只读状态查询
    Q_INVOKABLE bool    enabled(const QString& id) const;
    Q_INVOKABLE bool    checked(const QString& id) const;
    Q_INVOKABLE QString label(const QString& id) const;
    Q_INVOKABLE QString shortcut(const QString& id) const;

    // 触发（皮肤壳 / 快捷键唯一入口）
    Q_INVOKABLE bool invoke(const QString& id, const QVariantMap& args = {});
signals:
    void stateChanged();   // enabled/checked 变化 → QML 菜单/工具条刷新
};
```

- **注册点**：`main.cpp` 装配时注册试点四类动作；处理器先包装 SessionController 现有函数（迁移期兼容），验证后逐步内联；
- **快捷键**：注册表生成 `QShortcut`（或 QML Shortcut 查表），`onActivated → invoke(id)`；现有「文本输入焦点让行」（`textInputFocused`）逻辑保留在 QML；
- **皮肤触发**：`UiActionRegistry.invoke("edit.undo")` —— L3 皮肤与默认壳同一 API（doc/08 §3.5 第 5 条契约）。

## 6. QML 侧消费

- context property：`UiActionRegistry`（与 `Theme` / `beatbench` 并列，见 main.cpp 装配）；
- 菜单/工具条：`Repeater` over `ids()`，`enabled(id)`/`label(id)` 驱动按钮态，点击 → `invoke(id)`；
- 快捷键自动生效（注册表生成），QML 不再手写 `Shortcut`；
- 迁移期间：SessionController 旧函数保留，处理器内部先调用旧函数（包装层），逐动作验证后替换。

## 9. 皮肤系统契约衔接（doc/08 §3.5 增补）

- **第 5 条稳定契约 = UiActionRegistry API**（id 集 + invoke + 状态查询）：皮肤壳与默认壳同 API；
- L3 皮肤重写 chrome：菜单/工具条 = 枚举动作注册表（不再硬编码）；
- `keymap.json`（M7+）：动作 id → 快捷键覆写，皮肤包可携带（优先级：内置 < keymap.json）。

## 10. 扩展性衔接（doc/06）

- **注册面即扩展点**：`CodecRegistry`（格式）/ `cmd::Registry`（命令）/ `UiActionRegistry`（UI 动作）三注册表并列；插件（M8+）= 向注册面注册的调用方，加载机制（plugin.json + 权限审批）后置；
- 动作注册表不接插件进程（UI 侧私有）；插件命令经 `cmd::Registry` 出现后，皮肤/界面可按需触发。

## 11. 验收标准（总）

1. Main.qml 无硬编码 Shortcut，菜单/工具条从注册表枚举；
2. 最小 L3 测试皮肤可 `invoke` 四类试点动作；
3. SessionController 不再持有动作定义（只剩处理器）；
4. 现有 246 测试不降级 + 新增 UiActionRegistry 单测；
5. 图（`local/archify/beatbench-architecture-v3.html`）中「规划」虚线边全部转实线（现状兑现）。

## 12. 待拍板（后续）

- 动作 id 是否进 `capabilities` 协议（CLI 可见）？——建议不进（UI 动作是 GUI 私有；除非将来远程 UI）；
- `checked` 状态存储位置（注册表 vs 调用方）——建议调用方自持、注册表只读查询；
- 子菜单/分组的元数据（`menuPath`）——建议 v1 用 `category` 生成一级菜单，L2 `layout.json` 定稿时再细化。

### 13.2 未实现 / 偏差（与 §5–§7 的差距）

1. **处理器未迁入**：main.cpp 注册的 24 个动作 `handler` 全部是
   `[](const QVariantMap&){ return true; }`；注释写着「处理器暂时包装 QML 函数调用」，但实际
   没有包装——QML 调用方式是 `{ uiActions.invoke("file.open"); fileDialog.open() }`
   （invoke 空转后仍直接调 QML 函数）。§6「迁移期间处理器内部先调用旧函数」未做。
2. **enabled 谓词未接**：全部 `nullptr` → `uiActions.enabled(id)` 恒 true；QML Shortcut/菜单
   仍用自带的 `enabled:` 表达式。注释提到「QML 侧可通过 setEnabled 覆写」——**该类不存在
   `setEnabled`**（API 缺口，注释误导）。
3. **checked 未打通**：注册时 `checkable:true` 的 toggle 动作，checked 值无人写、无人读
   （QML 各自绑定 `showGrid`/`showExtras`/`currentPage`）；§12 建议「调用方自持、注册表只读查询」
   正好相反——现在注册表自持但没入数据，是**死状态**。
4. **快捷键未生成**：Main.qml 仍有 **14 个手写 Shortcut 元素**（`sequence: uiActions.shortcut(...)`
   查表、`onActivated` 内联真实逻辑）；§7 验收「Main.qml 无硬编码 Shortcut」未达成（硬编码的是
   Shortcut 元素与行为，非快捷键字符串）。
5. **菜单/工具条未枚举**：菜单栏 5 个 Menu 手写、MenuItem 手写（文本查表）；工具条按钮手写；
   `ids()/idsByCategory()` 未被消费。
6. **两个注册动作无消费方**：`view.toggleChannelIds`、`tool.toggleLn`（Main.qml 对应控件仍是

### 13.3 两条可选路线（建议先拍板再动工）

- **路线 A（继续迁移，按本稿 v1 完成）**：① 补 `setEnabled` + 把 enabled 谓词/真实 handler 迁入
  C++（handler 内 c++ 侧组合协议命令或回调 QML，先保行为）；② QML 快捷键/菜单/工具条改为
  `ids()/idsByCategory()` 枚举 + `enabled(id)/checked(id)` 驱动；③ 删死注册动作或接上；
  ④ 新增 Qt 侧单测。优点：兑现 L3 皮肤契约；缺点：本轮工作量集中在 UI 壳重构。
- **路线 B（降级为「动作目录」）**：文档/实现改为「注册表 = 动作 id 元数据目录（label/shortcut/
  category），行为仍在 QML」，并把 invoke 从 QML 调用处摘掉（避免「看似注册了实际没注册」的
  误读）；L3 皮肤再另行定义触发契约。优点：诚实、改动小；缺点：L3 皮肤壳仍拿不到行为入口，§9
  契约要改口径。
- **建议**：路线 A（与 doc/08 §6 待办、L3 皮肤前置一致），按 §7 验收逐条完成。
