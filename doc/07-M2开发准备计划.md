## 2. 构建命令（已实测）

> 终端：**Git Bash 为默认**（2026-08 起，避免 PowerShell 编码/引号问题）。以下为 bash 语法。

```bash
# 全新配置 + 构建 GUI（tests OFF，避免联网拉 GoogleTest）
cmake -S . -B build-gui -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH="G:/Qt/6.11.1/mingw_64" \
  -DCMAKE_CXX_COMPILER="G:/Qt/Tools/mingw1310_64/bin/g++.exe" \
  -DCMAKE_MAKE_PROGRAM="G:/Qt/Tools/Ninja/ninja.exe" \
  -DBEATBENCH_BUILD_TESTS=OFF
cmake --build build-gui --target beatbench
# 产物：build-gui/app/beatbench.exe

# 部署 Qt DLL 到 exe 旁（QML 应用必需，否则双击报找不到 Qt6Core.dll 等）
# --qmldir 必须指向 QML 源码目录，否则缺 QuickControls 插件
/g/Qt/6.11.1/mingw_64/bin/windeployqt.exe --qmldir app/qml build-gui/app/beatbench.exe
# 之后直接双击/运行 exe 即可，无需设 PATH；rebuild 只换 exe，DLL 无需重部署

# CLI + 测试回归仍用原 MSVC 目录（如需重建）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=ON
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure
```

要点：
- **Git Bash 路径映射**：`H:\...` → `/h/...`，`G:\...` → `/g/...`；bash 的默认 `g++` 是 `/c/MinGW/bin/g++`（太老，不支持 C++20），**构建必须显式 `-DCMAKE_CXX_COMPILER` 指向 Qt 自带 mingw1310**；
- `build-gui/` 已加入 `.gitignore`（2026-08），永不提交；
- GUI 开发期间 `BEATBENCH_BUILD_TESTS=OFF`；core 逻辑回归交给 MSVC `build/`。
  若网络可用，也可在 build-gui 开 tests（GoogleTest 支持 MinGW），但非必需；
- **M2 起步已完成**（2026-08）：QML 页面式外壳 + CommandDispatcher 桥接 + 第一条真链路（`b08be35`）；
- MinGW 的 `-Wall` 比 MSVC `/W4` 更严，core 暴露 1 处既有警告：
  `core/src/bms/bms_parser.cpp:337` 未使用变量 `data`——顺手清理（M2 首个小 commit 可带上）。

## 3. M2 起步路线（✅ = 已完成，提交 b08be35）

**节奏纪律：壳与纯视觉可用假数据占位；每个功能第一版必须走真命令全链路
（对话框 → `global_registry().dispatch()` → 模型 → 视图），不允许「整块先假、以后统一换真」。**

1. ✅ **Workspace 外壳（QML 壳）**：`QQmlApplicationEngine` 入口 + `Main.qml`（菜单/工具条/三栏/页面条/状态栏，
   对照 `doc/beatbench-ui-preview.html` 直译）；布局用 QML 原生，不用 QDockWidget；
2. ✅ **core↔QML 桥接层（app/bridge）**：`CommandDispatcher`（QObject 包装 `dispatch()`）已落地；
   `ChartModel` / `TimingEngine` 包装待时间轴时补（doc/08 §4）；
3. ✅ **第一条真链路**：打开谱面（文件对话框 → `dispatch(info)`）→ QML 元信息表单——全栈已验证；
3.5. ✅ **主题基线（2026-08，M2 立规矩落地）**：
   - `app/bridge/ThemeManager.hpp`：L1 token 单点（Q_PROPERTY 只读，值 = `doc/beatbench-ui-preview.html` `:root`），
     经 context property `Theme` 供 QML 全局读取；**界面颜色/字体禁硬编码**（doc/07 §4）；
   - 全局深色：`QQuickStyle::setStyle("Fusion")` + 深色 QPalette（main.cpp，值同样来自 ThemeManager）；
   - 控件样式基线（默认皮肤组件库）：`BbToolButton`（.tb/.tool-btn 两种样式）、`BbTabButton`（.dock-tab），
     PageSwitcher/MetaPanel/各页全部去硬编码；
   - 页面切换修正：三栏布局移入 `EditPage.qml`，内容区 StackLayout 真正切页（编辑/切音/测试）；
   - 调试参数（视觉迭代/验收）：`beatbench.exe --screenshot <png> [--page 0|1|2]`——grabWindow 抓帧保存后退出
     （外部窗口捕获对 RHI/D3D 内容不可靠，勿用）；
   - **字体（2026-08 跟进）**：默认黑体 `Microsoft YaHei UI`（Win 自带；备选 Noto Sans SC，OFL 可随包分发，

   - **分栏可拖拽（2026-08 跟进）**：EditPage 三栏 = QML 原生 `SplitView`（初始 左 240 / 中自适应 / 右 230，
     最小 180/320/160）。⚠️ **Qt 6.11 SplitView 附属性是 `SplitView.preferredWidth/fillWidth/minimumWidth`
     而非 `Layout.*`**（后者一律塌成 0 宽，实测踩坑，勿回退）；
   - **i18n 准备（2026-08 跟进）**：QML 全部用户可见字符串已 qsTr（下一步面板开发保持）；

## 5. 风险清单

1. **两套构建目录并存**（MSVC build/ 回归 + MinGW build-gui/ GUI）：提交前确认产物不混淆；
2. GoogleTest FetchContent 需联网（build/_deps 已有缓存，MSVC 侧无碍）；
3. 预览 HTML 是**设计参照不是移植源码**——QML 是声明式文本，对照直译组件树/属性，别把 C++ Widgets 习惯带进 QML；
4. MinGW 警告比 MSVC 多（§2 已列一处），新增代码尽量零警告；
5. **QML 双语言纪律**（doc/08 §2）：逻辑放 C++（bridge），QML 只管表现，JS 别写散——写进 code review 清单；
6. QML 首次加载/场景图初始化略慢、体积略大：可接受，发布时 qmlsc 预编译缓解（doc/08 §2）。
