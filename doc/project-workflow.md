# M7 设计：项目与文件资源管理

> 本文定义设计目标、边界与安全契约，不记录开发分期、完成进度或验收流水。**当前 B 只读；§4.5 的 B 编辑与跨窗格移动是设计目标，不是现有能力。**
> 关联：[模型与命令架构](<core-model.md>)、[命令协议](<command-protocol.md>)、[GUI与皮肤](<skin-system.md>)；实现细节以代码及其头注释为准。

## 1. 目标与边界

一个项目对应**一首歌的文件夹**，包含多个难度/模式的谱面与共享音频、BGA、图片等文件，允许内部子目录。子目录属于这首歌，不由扫描自动转成多曲合集或数据库。

先解决：看清项目有哪些谱面与资源、资源被哪些谱面引用、缺失在哪里、如何导入和重定位。然后支持谱面对比，尤其是编辑时左右参照另一张谱面。

### 已确认的范围

- 项目以文件夹为入口，不要求先创建专有项目文件。
- **独立项目页为主，资源表为主、目录树辅助**。
- **范围**：不增加程序内资源复制导入，复制由系统文件管理器完成；程序负责把资源定义应用到项目页勾选谱面，不因文件复制自动分配 WAV/BMP ID。
- 缺失重定位先列全部受影响引用，用户勾选后应用。
- 引用修改成为各谱面独立的未保存修改，支持逐谱撤销，之后统一保存。
- A/B 左右各显示一张谱面，宽度可调、可交换，可选择视口同步；当前左侧编辑、右侧只读，B 编辑目标见 §4.5。
- A/B 播放主谱 A，不因 B 获焦改变。

### 后置范围

- 普通磁盘文件的复制、移动、重命名、删除等继续使用系统文件管理器，不新增程序内复制导入。多谱资源绑定更新、谱面引用重定位属于当前范围。
- 打包：BMS 文件夹目前可以手动压缩，不作为资源管理或对比的先期验收条件。
- 多曲合集工作区、数据库、专有项目/工作区持久化格式。
- B 编辑的设计目标见 §4.5；不同文档跨窗格传递未获授权，播放来源不随焦点切换。
- 编码转换、广泛批量 note 变换保留为候选；自定义片段的元信息/定义/明确数据组更新按 §3.2 约束，不扩大为任意转换工具。

### 架构边界

- Project 做索引与分析，不把多个谱面合并成一个文档。每张谱面独立 `EditorSession`、undo、脏标记和保存。
- 不做改 A 自动改 B 的实时内容联动；资源重定位是显式选择范围的操作。
- core 格式无关、零 Qt，命令作为操作入口；GUI 展示与确认，CLI 可复用查询能力。
- `#WAV` 占用查询属于 core/project 与项目展示，不放进 `SliceWorkspace`。
- M7 不承担 SliceWorkspace 拆分、i18n、试玩判定或 L2 布局皮肤。

## 2. 项目与资源的对象区分

| 对象 | 作用 |
|---|---|
| 项目根目录 | 一首歌的文件范围，允许子目录 |
| 谱面条目 | 路径、格式、元信息、诊断、按需统计；打开后对应独立文档会话 |
| 磁盘资源 | 项目中的实际文件，也能显示谱面引用但缺失或位于项目外的目标 |
| 谱面内定义 | 某张谱面的 WAV/BMP ID 与声明路径；不同谱面可以用不同 ID 指向同文件 |
| 引用关系 | 文件 ← 谱面 / 定义 ID / 头部字段；有需要时再补事件使用位置 |

**项目资源表以文件为单位；现有采样面板以当前谱面的槽位为单位。**不能把“没有 note 使用某个 WAV 定义”和“磁盘文件没有任何谱面引用”混为一谈。

**资源表收录范围**：识别**当前文件夹内的全部相关文件**——谱面（`.bms/.bme/.bml/.pms`）、
音频、图片、视频；用户不需要手动把文件拖进来。**排除应用生成物**（`<谱面>.bak` 崩溃备份、切音导出目录）
与其它类型（`.txt` 等），否则“未被引用”的结论会被自己的备份文件污染。
“磁盘文件没有任何谱面引用”因此成为**可见信息**（DAW 漏导出、BGA 换版这类修复场景正需要它）。

**排除只作用于目录枚举，不作用于已解析引用**（正确性要求，非偏好）：任何被谱面引用到的文件都必须出现在
资源表里——切音导出目录中的成品切片尤其如此，它正是资源更新（§9.6）的操作对象。备份/缓存可隐藏；
已绑定但无引用的旧切片可标注来源、默认折叠，但不能仅凭所在目录名判定为无关。资源表口径为
“当前已解析引用”，不声称穷尽 `#RANDOM/#IF` 全部分支（§9.7）。

资源查询应区分：

- 项目内实际文件与谱面声明的目标；声明目标不存在时仍应有缺失条目。
- 被哪些谱面定义或封面字段引用。
- 已定义，但没有已知事件使用。
- 磁盘文件没有已知谱面引用；这类文件可能是创作源文件或附带文档，不能因此推定应删除。
- 文件位置、实际可用性和路径兼容提示是不同信息。缺失、外部路径、扩展名替代、大小写差异的具体显示与匹配规则见 §8 待补。

索引应保留谱面、定义 ID 或头部字段等引用出处，不能只用总计数代替关系。扫描不应要求加载或解码音频；基础信息尽早出现，完整统计按需补齐。换根、取消或刷新后不得发布旧结果。已打开的未保存内容与磁盘扫描结果必须区分。

实现入口：[项目模型](<../core/include/beatbench/core/project/Project.hpp>)、[扫描](<../core/src/project/scan.cpp>)；线程、模型发布和缓存机制不在本文复述。

## 3. 资源管理

### 3.1 打开与浏览

- 文件菜单打开歌曲文件夹，进入独立项目页。
- 谱面列表与资源表提供独立入口；目录树辅助定位。
- 资源表可查看路径、类型、可用状态和引用谱面；选中文件查看具体谱面 / ID / 字段。
- 打开谱面仍使用现有文档会话；浏览资源详情不要求打开谱面音频。
- 当前编辑页的元信息、采样、lint、BGA、属性与时间轴保持单谱职责。

### 3.2 多谱资源绑定更新（不做复制导入）

- 文件复制交给系统文件管理器；绑定更新不复制资源、不自动分配 ID、不自动铺放音符。
- 目标必须明确勾选；空集合不回退当前 A。已打开的脏谱使用内存内容；操作不得切换 A/B。
- 简易 WAV 更新与自定义片段应区分。自定义片段用于元信息、定义或明确数据组，不是整谱替换，也不承诺按原文行号插入或保留原始空白/网格字节。
- 预览列出目标、旧值与新值；数据组替换须标明小节、源通道和替换范围，不得伪装成追加。覆盖已有字段、定义或数据组须明确确认；输入或目标变化后原授权失效。
- 为避免重解释旧音符，结构指令、随机条件控制流和块注释不属于片段更新支持范围；不支持内容的警告不等于授权解释任意结构。具体解析限制以实现为准。
- ID 按各目标的既有进制解释，不修改进制。资源相对路径以项目根解释，再换算到各目标谱面目录；使用项目内可移植路径，不因资源尚不存在而隐式复制文件。
- 提交前校验目标身份、路径与内容版本；输入、目标集合或项目根变化必须重新预览。取消不改内容，同值不增加撤销步。
- 每谱一个可独立撤销的编辑操作；本次应用不自动保存谱面或资源，改动留在内存等待显式保存。
- 保存勾选谱面不得扩大到未勾选的脏谱，保留既有草稿、保存失败及格式确认纪律。
- 项目资源表是磁盘扫描快照，不冒充内存实时引用索引；未保存定义在编辑页检查，显式保存后刷新项目目录。

### 3.3 缺失重定位（设计目标）

- 从缺失条目发起查找替代文件。
- 展示原路径 → 新路径，以及全部受影响谱面和 ID / 字段。
- 用户勾选应用范围后修改引用，不静默改全部谱面。
- 每张目标谱面有独立撤销步；不直接覆写其磁盘文件。
- 修改后标为未保存，可以检查、撤销，再统一保存。
- 保存与关闭流程需汇总项目内未保存谱面；保留已有确认纪律。
- 应用前预览所选范围，取消不修改内容；输入或目标变化须重新确认。最终查找入口、候选选择与界面布局仍待讨论，不在此定案。

### 3.4 资源管理正确性要求

- 同歌多谱面与内部子目录正确列出，资源浏览无需音频解码。
- 同一文件被多谱不同 ID 使用时，详情能准确列出引用关系。
- “已定义未使用”和“磁盘无已知引用”正确区分。
- 文件复制由系统文件管理器处理；绑定更新不会复制文件或隐式铺放音符。
- 重定位可以只改勾选谱面；各谱可独立撤销；未保存前磁盘谱面保持原内容。
- 统一保存与关闭确认不会遗漏被资源修复修改的谱面。

## 4. 谱面对比与编辑 A/B

### 4.1 编辑布局

- 左右各显示一张谱面，中间分隔线可调整宽度。
- 提供交换左右功能。
- 当前左侧可编辑、右侧只读；交换后原右谱进入左侧成为编辑对象。
- 当前采样、属性、编辑命令、撤销与保存保持明确的单谱归属，不能因右侧点击自动修改错误文档。
- 两张谱面的文档状态独立，交换只是显示角色变化。
- 此 A/B 双谱布局与现有播放 A-B 循环点是不同功能，命名与入口需区分。

### 4.2 视口同步

同步的是**视口**，沿用现有编辑器滚动与定位逻辑。

- B 头部提供默认开启的“同步”开关（会话态、不跨重启保存）；开启/重开对照时以 A 当前视口为准，关闭后两侧独立导航、缩放。分割仍由拖边缘展开，不增加控制分割显示的 checkbox。
- 原有会导致视口改变的入口，对参与同步的已开启谱面视图应用相应操作；关闭同步时各视图保持独立。
- 滚轮、拖动、跳转、播放跟随、seek、缩放等改变视口的入口都应遵守同步开关，不只同步滚轮。
- 同步使用连续的“小节号＋节内位置”拍位，而非复制像素偏移、歌曲百分比或秒数；各谱按自己的小节长度换算。水平通道滚动与列布局保持独立。
- 各侧遵守自己的可滚范围；较短 B 到边界后不扩展或编辑文档，不反向拉回 A。结构不兼容时明确提示，不承诺所有网格线重合。
- 结构提示不等于音符/编排 diff。B 不发声、不 seek；同步播放头只是将 A 的拍位映射到 B，播放跟随仍遵守 A 的规则。

### 4.3 播放与编辑归属

- 只播放主谱 A，不做两谱同时出声的混合播放；B 获焦不切换播放来源。
- 属性 Dock、保存与播放固定归 A，B 获焦或被编辑不改变 Ctrl+S 的保存对象；退出仍检查全部文档的未保存修改。B 编辑须显式指向 B 文档，不能误改 A 的旧选区；设计目标见 §4.5。

### 4.4 对比分析候选

统计（note/LN/密度/BPM）、结构（元信息、定义表、timing）与语义 diff 是候选，具体指标和统计口径尚未确认。简单参考叠加按 §9.5 定义，不等于音符 diff，不据此承诺难度判定或资源匹配。

### 4.5 M7 剩余需求：同文档分栏 BGM 编排（未实现）

- **设计目标，非现有能力**：B 能显示并展开 BGM 通道；A/B 绑定到同一文档时，可跨窗格移动音符，分别查看不同横向区域，避免大量 BGM 子通道间反复水平滚动。
- **B 编辑也是明确目标**，不只为同文档移动预留一个开关。B 获焦不得切换活动主谱 A，也不得切换左右任一 Dock 的文档归属；Dock 仍属于 A。
- B 放置沿用**当前选中采样 ID 的文字**，按 B 的既有进制校验；即使 A/B 来自不同歌曲，也不按资源名称、路径或声音身份重新映射，不自动复制资源或定义。A 为 Base62、B 为 Base36 且选中 ID 含小写字母时，直接禁止放置，不转换大小写、不改 ID、不重编码。
- 同文档跨窗格移动属于目标；**不同文档跨窗格复制/移动尚未获授权**，不能因允许 B 编辑便自动扩展。
- 具体输入交互、选区归属、同文档共享撤销和误操作保护仍需设计；本节不决定最后点击侧播放或完整双侧 UI。
- **当前边界不变**：B 只读；B 编辑和跨窗格移动都不能写成已经交付。

## 8. 仍需细化的问题

下列行为尚未确定，不应将实现方便的默认值写成“用户已拍板”；已确认契约见 §9，未决项不构成最终界面或功能授权。

1. 打开单谱是否自动扫描所在目录；从子目录打开时如何识别歌曲项目根。
2. 扫描范围与忽略规则、符号链接、刷新与外部改动；已打开未保存文档如何参与资源索引。
3. 缺失候选匹配规则、扩展名回退与大小写提示、外部引用的新路径写法。
4. 程序内资源复制导入不在范围内；多谱定义与显式数据组更新按 §3.2 处理，控制块和结构指令仍拒绝，不自动分配新 ID。
5. RANDOM/IF 等尚未完整支持的结构对“无已知引用”的可信度；不能据此静默删除或裁剪文件。
6. A/B 当前只读边界与拍位同步见 §4.2、§9.5；B 编辑与同文档分栏移动的设计目标见 §4.5。
7. 谱面对比的第一批指标、统计口径仍待细化。可选本地谱面快照契约见 §9.8；ZIP 模板与广泛批量变换随对应功能后置讨论。

## 9. 工作流与安全契约

### 9.1 职责分离

项目页提供索引、文档选择和显式目标集合；只读浏览不应隐式写盘。文档分配、视口同步、资源修改与持久化是不同操作，不得用一个活动会话变量替代全部归属。开发排期和验收记录不构成公开产品契约。

### 9.2 项目页兼任“已打开文档”视图

- 不另增顶部/底部标签条，项目页集中展示已打开与未保存状态；未加载、清洁会话和存在未保存内容必须可区分。
- 点击已打开谱面复用内存会话，不重新读盘覆盖未保存修改。
- 选择器起点记忆不等于自动恢复项目；取消或扫描失败不改变成功目录记录。

### 9.3 切音目标 = 项目页勾选集合（唯一真相源）

- 切音的**唯一真相源 = 项目页勾选集合**。
  编辑页显示哪个谱面是**另外选定**的（项目页里打开，或直接打开文件）。
- 因此必须在**切音页显著显示目标**（勾选 N 个 / 当前编辑谱 / 无目标三种文案）+ 项目页顶部
  显示勾选数；目标变化且切音有未保存内容时应提示。否则“看着 A 谱、切音存进 B”极难察觉。
- 文件模式（直接打开文件、没有项目页）下，真相源退化为“当前编辑页打开的谱面”。
- **发起操作时固定目标集合**：预览与提交读同一批 `targets[]`
  （session/路径 + 文档版本），不在执行中途改读 UI 当前选中；应用前校验文档版本，
  避免长时间切音后把旧计划写进已变的内容。用户改项目选择时，应显式重新预览。
- **目标集合的选取方式**：项目页谱面列表每行一个
  checkbox，列头为全选；**勾选非空 = 目标集合 = 勾选项**；**未勾选任何谱面 = 目标退化为
  “当前编辑页打开的谱面”**（也覆盖“新建未保存谱面”这种没有磁盘路径的情况）。
  勾选是**临时集合**，不写盘、不进入谱面内容、不留到下次启动（无项目文件，§9.7）。
- 按明确文档身份/路径寻址；按需加载目标不得改变活动 A。执行期间不改读 UI 临时选中项。

**切音安全契约**：

- 预检使用可见输入值、固定目标与内容版本；无效输入或不可用目标须在写出前拒绝，预检不写 WAV、不修改谱面。
- ID 占用考虑定义、已有 note 引用与 LNOBJ；空位分配、覆盖已有 ID 或取消应明确选择。ID 覆盖可能改变旧音符声音/LNOBJ 语义，不能静默执行，亦不等于授权覆盖磁盘音频。
- 文件重名列明落点、冲突与固定目标；覆盖、续号、取消分开确认。覆盖音频可能影响其他谱面，且不随谱面 undo 恢复；续号保留旧文件。不得覆盖目录、符号链接落点或参考音频自身。
- 输入、素材、目标或版本变化使计划失效；提交前重新核对最终磁盘落点，取消不写音频、不编辑谱面。
- 音频输出一份，各目标使用符合自身目录的资源路径；每谱独立撤销铺放，不自动保存谱面。
- 文件输出与谱面铺放分别反馈；部分失败明确已产生的结果，不提供包含失败文件的可用结果。不承诺跨文件回滚或跨进程输出锁。

### 9.4 对照布局：拖拽分割，不加 checkbox

中央区通过边缘拖条展开或收起副窗格，中间分隔线可调宽；收起保留文档和视图状态，不把布局变化当作编辑。

### 9.5 独立视图与文档绑定

- 每张文档独立持有内容、路径、dirty 与 undo；同一文档的两个视图共享文档内容，各有视口和选择。打开已有路径复用实例，新建不覆盖当前谱面。
- A/B 显式绑定文档身份；更换活动 A 不得暗中改变固定 B。交换只改变显示角色，不复制文档、不重读内容、不重置撤销；先完成草稿确认，取消或失败不交换。
- 项目页分配 B 不激活 A、不改 A 草稿或播放来源；加载失败保留原 A/B。
- 当前只读 B 可选择和导航，但不放置、移动、删除或试听。点击 B 后修改类动作不得落到 A 的旧选区；属性 Dock、保存和播放仍属于 A。未来 B 编辑归属按 §4.5 区分。
- B 次要通道与波形的隐藏只影响 B 显示，不改文档或 A 布局；查看或展开空 BGM 通道不产生 dirty 或撤销步。
- 分栏各用自己的列布局；叠加借用 A 几何，不能把叠加当作第二个独立输入面。

**同屏参考叠加范围**：

- 可在同屏叠加与 A/B 分栏间切换，保留 B 选择、分栏宽度与拍位；B 以单色半透明参考绘于 A 下方，可隐藏及调整透明度。
- 纵向按 A 小节长度/方向/缩放投影小节与节内位置，不使用 B 秒数、不自动对齐歌曲偏移；横向按 Lane 映射到 A 已有列，不增加 A 列。
- 支持普通音符、LN 和地雷；BGA/BPM/STOP 不作为参考音符。无法映射、隐藏或结构不同的内容明确提示。
- B 更长时只扩展查看范围，不扩展 A 可编辑范围，不产生修改，不在 A timing 外伪造秒数或触发音频定位。
- 叠加输入只属于 A，B 不命中、不试听；不计算仅 A/仅 B/共有分类，不比较资源身份，不做自动偏移、难度判定或混播。

### 9.6 实际制作流程与批量功能强度

本节是用户描述的常规工作流，不代表所有作者的唯一做法：

1. 曲师完成歌曲，切音负责人制作模板：所有 note 先位于 `01` 背景通道，确认播放与 DAW 中一致。
2. 谱师以模板制作不同难度，通常不额外添加空音，主要将部分背景 note 平移到游玩轨。特殊情况包括手写 `#RANDOM` 或为部分难度单独改变歌曲。
3. 制作中或完成多谱后，偶尔需要更新切音/BGA。负责人通常提供原始 BMS 字段，作者手动逐谱复制到受影响文件；批量功能主要减轻这项重复劳动。

**批量功能目标**：支持多选受影响谱面，将负责人提供的字段或切音/资源绑定结果应用到这些目标；目标可预览、每谱可撤销、修改后统一保存。多选目标不能被实现成仅“当前活动谱面”。

**无需扩展为自动重切迁移系统**：首期不要求自动识别旧新切片对应关系、记录稳定切片血缘、处理任意拆片/并片后自动保住旧编排，也不要求强制版本化资源文件。负责人提供的更新内容是输入，不由软件猜测意图。

自定义片段按 §3.2 实现：字段/定义更新与新增note铺放分开，保存遵循正常codec顺序，不按原文位置插入；显式数据组替换在预览列出小节/源通道和范围，不能把“应用切音结果”默认解释为再次追加整份背景模板。控制块与结构指令仍有限制，风险警告不表示已支持任意内容。

常规流程下，多难度对比主要服务于**同一音乐素材如何分配到背景与游玩轨，以及游玩轨的编排差异**。比较总 note 数不能单独代表难度差异；同一个音乐事件在两谱里换轨是有意义的编排变化，不应仅当成无关的删除与新增。具体差异分类仍属于对照功能细化。

### 9.7 其它边界

- 索引只描述当前已解析引用，不声称穷尽 RANDOM/IF 分支；遇到不支持的控制结构须警告，不能据“无已知引用”静默删除或裁剪文件。
- 不引入专有项目文件；项目临时选择/筛选/同步不构成持久化项目格式。这不表示应用不产生备份等附加文件，也不承诺崩溃恢复所有未保存文档。
- 资源可用性、路径兼容与事件使用是独立维度；统计未完成须明确显示，不能先把未知当成零引用。

### 9.8 可选本地谱面快照

- 面向不熟悉 Git 的作者，只呈现时间戳与可空备注；纯本地、默认关闭，无账号、远端同步、分支或自动合并，不接管用户仓库。
- 保存与创建快照是不同结果；沿用既有草稿/格式确认和保存失败处理，取消不创建快照。快照失败不回滚成功保存，无变化不重复记录。
- 范围为已保存谱面文件，不含历史媒体；不承诺恢复被覆盖的 WAV，不称完整项目备份，不替代未保存确认、undo 或崩溃恢复。
- 查看其他谱面历史不打开或切换文档；保存并创建快照须面向明确的当前目标。
- 恢复在原谱面目录创建唯一命名副本，保留后缀和相对媒体基准，绝不覆盖原文件、不重载当前会话。
- 可选退出快照仅处理干净、已命名文档，放弃的修改不记录；失败阻止本次退出，允许重试或明确关闭选项。关闭功能不删除历史。
- 历史按谱面路径隔离，路径变更后不自动迁移；容量限制须明确报错，不静默删历史。历史不随歌曲目录自动迁移，不替代异机备份；大历史和慢速目录的性能不作无界承诺。
