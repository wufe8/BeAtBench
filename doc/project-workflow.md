# M7 设计：项目与文件资源管理

> 状态：**M7 已有可用部分，未完成项明确标注为未实现**。项目索引、多文档、A/B 只读对照、拍位同步、参考叠加、可选谱面快照与多谱绑定更新已接入；缺失重定位与同文档分栏移动仍待实现。
> 关联：`doc/core-model.md`（模型/命令架构）、`doc/command-protocol.md` 三、（协议）、`doc/skin-system.md`（GUI）、`doc/development.md` 七、（状态）。

## 1. 目标与边界

一个项目对应**一首歌的文件夹**，包含多个难度/模式的谱面与共享音频、BGA、图片等文件，允许内部子目录。子目录属于这首歌，不由扫描自动转成多曲合集或数据库。

先解决：看清项目有哪些谱面与资源、资源被哪些谱面引用、缺失在哪里、如何导入和重定位。然后支持谱面对比，尤其是编辑时左右参照另一张谱面。

### 已确认的范围

- 项目以文件夹为入口，不要求先创建专有项目文件。
- **独立项目页为主，资源表为主、目录树辅助**；当前编辑页的采样绑定与文件手动管理已经可以闭环，新增项目侧栏不紧迫。
- **范围**：不增加程序内资源复制导入，复制由系统文件管理器完成；程序负责把资源定义应用到项目页勾选谱面，不因文件复制自动分配 WAV/BMP ID。
- 缺失重定位先列全部受影响引用，用户勾选后应用。
- 引用修改成为各谱面独立的未保存修改，支持逐谱撤销，之后统一保存。
- 后续编辑 A/B 左右各显示一张谱面，宽度可调，可交换，可选择同步滚动和位置；首期允许左侧编辑、右侧只读。
- 首期 A/B 播放左侧谱面。

### 后置范围

- 普通磁盘文件的复制、移动、重命名、删除等继续使用系统文件管理器，不新增程序内复制导入。多谱资源绑定更新、谱面引用重定位属于当前范围。
- 打包：BMS 文件夹目前可以手动压缩，不作为资源管理或对比的先期验收条件。
- 多曲合集工作区、数据库、专有项目/工作区持久化格式。
- 不同文档的完整双侧编辑仍后置，播放来源切换未定；这不推迟 §4.5 已纳入 M7 的同文档分栏移动需求。当前 B 仍只读，播放仍属于 A。
- 编码转换、广泛批量note变换等保留为后续候选；自定义片段的元信息/定义/明确数据组更新已纳入 §3.2，不扩大为任意转换工具。
  （**叠加姿态**已不在后置范围：排入 §9.1 阶段 2.5，呈现形态见 §9.5；仅具体差异指标口径仍开放，见 §8。）

### 架构边界

- Project 做索引与分析，不把多个谱面合并成一个文档。每张谱面独立 `EditorSession`、undo、脏标记和保存。
- 不做改 A 自动改 B 的实时内容联动；资源重定位是显式选择范围的操作。
- core 格式无关、零 Qt，命令作为操作入口；GUI 展示与确认，CLI 可复用查询能力。
- `#WAV` 占用查询属于 core/project 与项目展示，不放进 `SliceWorkspace`。
- M7 不承担 SliceWorkspace 拆分、i18n、试玩判定或 L2 布局皮肤。

## 2. 项目与资源的对象区分

| 对象 | 作用 |
|---|---|
| 项目根目录 | 一首歌的文件范围，允许子目录 |
| 谱面条目 | 路径、格式、元信息、诊断、按需统计；打开后对应独立文档会话 |
| 磁盘资源 | 项目中的实际文件，也能显示谱面引用但缺失或位于项目外的目标 |
| 谱面内定义 | 某张谱面的 WAV/BMP ID 与声明路径；不同谱面可以用不同 ID 指向同文件 |
| 引用关系 | 文件 ← 谱面 / 定义 ID / 头部字段；有需要时再补事件使用位置 |

**项目资源表以文件为单位；现有采样面板以当前谱面的槽位为单位。**不能把“没有 note 使用某个 WAV 定义”和“磁盘文件没有任何谱面引用”混为一谈。

**资源表收录范围**：识别**当前文件夹内的全部相关文件**——谱面（`.bms/.bme/.bml/.pms`）、
音频、图片、视频；用户不需要手动把文件拖进来。**排除应用生成物**（`<谱面>.bak` 崩溃备份、切音导出目录）
与其它类型（`.txt` 等），否则“未被引用”的结论会被自己的备份文件污染。
“磁盘文件没有任何谱面引用”因此成为**可见信息**（DAW 漏导出、BGA 换版这类修复场景正需要它）。

**排除只作用于目录枚举，不作用于已解析引用**（正确性要求，非偏好）：任何被谱面引用到的文件都必须出现在
资源表里——切音导出目录中的成品切片尤其如此，它正是资源更新（§9.6）的操作对象。备份/缓存可隐藏；
已绑定但无引用的旧切片可标注来源、默认折叠，但不能仅凭所在目录名判定为无关。资源表口径为
“当前已解析引用”，不声称穷尽 `#RANDOM/#IF` 全部分支（§9.7）。

资源查询应区分：

- 项目内实际文件与谱面声明的目标；声明目标不存在时仍应有缺失条目。
- 被哪些谱面定义或封面字段引用。
- 已定义，但没有已知事件使用。
- 磁盘文件没有已知谱面引用；这类文件可能是创作源文件或附带文档，不能因此推定应删除。
- 文件位置、实际可用性和路径兼容提示是不同信息。缺失、外部路径、扩展名替代、大小写差异的具体显示与匹配规则见 §8 待补。

模型可沿用 `Project{root_path,charts,resources}`、`ChartRef`、`ResourceRef`、展示分组。ResourceRef 需保留引用来源，不能只用一个计数代替关系。准确字段与命令参数在实现前细化。

**core 索引与扫描**：模型定义见 `core/include/beatbench/core/project/Project.hpp`，扫描实现见 `core/src/project/scan.cpp`。资源条目保留谱面/定义或头部字段/ID/引用数量等出处，不能用总计数替代引用关系。两段式扫描先枚举，再后台补解析、元信息、统计和引用；资源候选复用目录索引。

扫描目标：不加载/解码音频即可列谱面和资源；基础信息尽早出现，完整统计按需后台补。子目录遍历、取消、性能限制与刷新应围绕单曲项目设计，不能把已有扫描开头的默认限额当成产品定案。

GUI结果发布：规范路径、行数据、引用明细和汇总均在工作线程形成不可变快照；主线程只安装共享数据到自身拥有的列表模型，项目页按可见行取数，引用详情虚拟化。保留旧列表查询接口，但不在页面中把整表及所有引用转换为JS数组。换根/取消必须拒绝旧结果和旧错误；当前取消在core扫描阶段边界生效，不承诺中断单个正在进行的文件系统/解析调用。

## 3. 第一阶段：资源管理

### 3.1 打开与浏览

- 文件菜单打开歌曲文件夹，进入独立项目页。
- 谱面列表与资源表提供独立入口；目录树辅助定位。
- 资源表可查看路径、类型、可用状态和引用谱面；选中文件查看具体谱面 / ID / 字段。
- 打开谱面仍使用现有文档会话；浏览资源详情不要求打开谱面音频。
- 当前编辑页的元信息、采样、lint、BGA、属性与时间轴保持单谱职责。

### 3.2 多谱资源绑定更新（不做复制导入）

- 文件复制交给系统文件管理器；项目页复用既有谱面勾选集合，底部功能区固定两行紧凑控件：第一行编辑A/对照B/保存全部/保存勾选，第二行“自定义…”与内嵌单条WAV更新。较长说明放tooltip，不再把五按钮固定排三行。
- **简易WAV更新不弹窗**：直接输入两字符ID和文件名，应用到勾选谱面；已有ID变化时在页内警告并要求再次点击“确认覆盖”，修改输入/目标即取消原授权。不自动铺放音符。
- **自定义内容保留弹窗**：输入片段进入对应模型字段/结构，保存使用谱面codec正常的头部/定义/数据/raw写出顺序，不按原文行号插入，也不把片段当整谱替换。常驻警告：不受支持或无法识别的内容，可能无法插入到预期位置，保存后的位置和表现也可能变化；建议主要用于批量更新元数据或WAV ID，应用前检查预览。
- 元信息按字段更新，WAV/BMP/BPM/STOP按kind+ID更新；数据行按小节/源通道整组替换（含该组所有BGM子行），预览明确标识整组替换、不是追加。未知头字段透传；未识别raw按同KEY替换或保留输入文本，不承诺作用域/执行支持。未涉及模型事件/源身份及raw保留，不承诺原文件空白或网格字节不变。
- 为避免重解释旧音符，拒绝BASE/PLAYER/LNOBJ/LNTYPE/LNMODE/ENCODING等结构变更、随机条件控制流和块注释；PMS非当前写出profile的歧义别名通道拒绝。风险警告不代表支持这些结构。输入片段按目标已有进制、模式和定义上下文解析，不整谱序列化再解析。
- 关键字不区分大小写，ID保留大小写；BMP00可用、WAV00拒绝。文本最多1Mi字符，目标数×定义/输入行数最多20000行预览。无自动新旧切片匹配或切音编排迁移。
- 目标必须明确勾选；空集合不回退当前 A。已打开脏谱复用内存会话，未打开谱加载独立会话；预览/应用不切换 A/B。目标含随机/条件控制块时首版拒绝操作。
- 相对资源路径以项目根解释，换算为每张目标谱面目录的相对路径；首版只支持项目根内部可移植相对路径，不复制文件，也不要求资源已经存在。
- 逐目标按其现有 36/62 进制解释 ID，不修改进制；预览列出谱面、ID、旧路径→新路径。任何已定义且发生变化的 ID（含空定义）均算覆盖，必须勾选警告确认后才能提交；同值不改、不增加撤销步。
- 提交前全目标校验身份、路径与内容版本；输入、目标集合、项目根变化须重新预览。每谱一个复合编辑命令，可独立撤销，取消预览不改内容。
- 应用本次命令时暂时抑制自动保存/备份钩子，再恢复原设置：原谱面及资源不写盘，改动留在内存等待显式保存；后续普通编辑/撤销仍遵从用户原持久化设置。
- 全部已打开文档桥、当前元信息/采样/BGA/时间轴/lint面板与未保存徽标刷新；对当前A的结构更新清理旧选择/未完成LN引用，只改B不清理A选择。项目页资源/引用两表使用纵向可拖动分隔条分配高度，最小高度随短窗夹紧，不再固定引用区150px上限。项目资源表仍为磁盘扫描快照，不冒充内存实时引用索引；未保存定义在编辑页检查，保存后刷新文件夹更新资源表。无后台媒体文件监控，同路径媒体外部覆盖刷新不属于本次绑定操作。
- “保存勾选谱面”固定已打开脏目标的身份/路径/版本，逐谱复用既有保存及 PMS 后缀确认；取消/失败停止剩余目标并恢复原 A，不扩大到未勾选脏谱。保存全部和退出仍复用原有统一保存/确认流程。

### 3.3 缺失重定位

- 从缺失条目发起查找替代文件。
- 展示原路径 → 新路径，以及全部受影响谱面和 ID / 字段。
- 用户勾选应用范围后修改引用，不静默改全部谱面。
- 每张目标谱面有独立撤销步；不直接覆写其磁盘文件。
- 修改后标为未保存，可以检查、撤销，再统一保存。
- 保存与关闭流程需汇总项目内未保存谱面；保留已有确认纪律。

### 3.4 第一阶段验收

- 同歌多谱面与内部子目录正确列出，资源浏览无需音频解码。
- 同一文件被多谱不同 ID 使用时，详情能准确列出引用关系。
- “已定义未使用”和“磁盘无已知引用”正确区分。
- 文件复制由系统文件管理器处理；绑定更新不会复制文件或隐式铺放音符。
- 重定位可以只改勾选谱面；各谱可独立撤销；未保存前磁盘谱面保持原内容。
- 统一保存与关闭确认不会遗漏被资源修复修改的谱面。

## 4. 第二阶段：谱面对比与编辑 A/B

### 4.1 编辑布局

- 左右各显示一张谱面，中间分隔线可调整宽度。
- 提供交换左右功能。
- 首期左侧可编辑，右侧只读；交换后原右谱进入左侧成为编辑对象。
- 当前采样、属性、编辑命令、撤销与保存保持明确的单谱归属，不能因右侧点击自动修改错误文档。
- 两张谱面的文档状态独立，交换只是显示角色变化。
- 此 A/B 双谱布局与现有播放 A-B 循环点是不同功能，命名与入口需区分。

### 4.2 视口同步

同步的是**视口**，沿用现有编辑器滚动与定位逻辑。

- B 头部提供默认开启的“同步”开关（会话态、不跨重启保存）；开启/重开对照时以 A 当前视口为准，关闭后两侧独立导航、缩放。分割仍由拖边缘展开，不增加控制分割显示的 checkbox。
- 原有会导致视口改变的入口，对参与同步的已开启谱面视图应用相应操作；关闭同步时各视图保持独立。
- 开发时需盘点滚轮、拖动、跳转、播放跟随、seek、缩放等现有入口，统一处理，避免只有滚轮同步而其他入口漏掉。
- 本目标没有新增“按小节 / 按秒对齐谱面”的用户选项，没有修改谱面事件或 timing 数据的要求。
- **拍位锚点实现**：统一在各视口高度的 90% 处读取连续的“小节号＋节内位置”，不吸附、不取视口顶端（歌尾顶端可能只剩留白）。接收视图用自己的小节长度缓存换算滚动位置；不复制像素偏移、总曲百分比或秒数。共享纵向缩放/方向，水平通道滚动和列布局仍独立。展开B时A保留等高状态底栏，使实际绘图区上下边界一致，拍位锚点也在屏幕同一高度。
- A 的滚动、缩放、定位、播放跟随、几何及内容更新走统一锚点变更通知；B 的滚轮、拖动（包括中键）、滚动条、缩放、标尺/波形定位报告已完成导航。协调器合并一次事件中的变化、抑制应用时回入；B 的布局/内容刷新不能倒推 A。B 导航先提交给 A，再以 A 可达锚点回投 B，避免边界误差反复拉扯。
- 各侧遵守自己的可滚范围，较短 B 到边界后不扩展/编辑文档、不反向拉回 A；提示结构差异，不能保证不兼容结构的所有网格线重合。交换在草稿确认成功后捕获并恢复原 A 拍位，取消/保存失败不动视口。
- 时序/结构提示比较模式、有效小节长度、基础 BPM、BPM/STOP 事件与已用小节范围，忽略同范围内音符数量/采样/编排差异。差异说明常驻 B 底栏（悬停查看全文），同步开关始终可关；这只是同步风险提示，不是后续音符 diff。
- B 不订阅全局音频时钟、不 seek 或发声。同步开启时，只由 A 将播放头秒数转成拍位，再映射为 B 自己 timing 下的视觉红线；视口是否随播放移动仍遵守 A 的既有“跟随”规则。用户导航不自动关闭跟随，播放中下一 tick 可以按既有规则重新锁定；关闭同步后 B 不参与 A 的播放跟随。

### 4.3 播放与后续编辑

- **只播放主谱**：不做两谱同时出声的混合播放——合并时间轴在结构不一致时没有定义，
  且它最贵。副谱只用于“看”，不参与发声。同步视口按现有播放跟随规则参与更新。
- 右侧只读不意味着加载另一套 BGM 混播。
- 同文档分栏移动需求见 §4.5，可能需要 B 编辑支持，但不据此决定不同文档的完整双侧编辑或播放来源切换。

### 4.4 对比分析候选

原草案的统计（note/LN/密度/BPM）、结构（元信息、定义表、timing）与叠加 diff 保留为候选能力。用户已确认“资源管理之后做谱面对比”，并明确编辑双谱布局与**叠加姿态**（已排入 §9.1 阶段 2.5，与分栏共用内核，见 §9.5）；**具体分析指标与统计口径尚未确认**，不把旧草案的全部指标作为首期必做。“叠加播放”（两谱同时出声）已确定不做（§4.3）。

验收重点：两谱能同时显示，宽度可调、可交换；右侧内容不可编辑；所有视口变化入口遵守同步开关；左侧命令只改左谱；播放来源明确。

### 4.5 M7 剩余需求：同文档分栏 BGM 编排（未实现）

- **用户要求，尚未实现**：B 侧能够显示并展开 BGM 通道；A/B 绑定到**同一文档**时，可在两个分栏窗格之间移动音符。通过两侧独立查看不同横向区域，避免 BGM 子通道很多时反复水平滚动。
- 此需求与**缺失资源重定位**并列为 M7 剩余功能，不把它笼统归入“以后双侧编辑”。既有 B 次要通道显示开关或同文档查看能力不等于该工作流已完成。
- 实现可能需要开放 B 编辑支持；具体输入、源/目标文档身份、共享撤销与误操作保护须在后续设计/实现中明确。本需求**不决定不同文档的完整双侧编辑，也不决定播放来源切换**。
- **当前已实现状态不变**：B 只读；编辑、属性、保存和播放仍归 A。跨窗格移动及 B 编辑支持均需后续实现。

### 9.2 项目页兼任“已打开文档”视图

不引入顶部/底部标签条：项目页列出谱面时就标注**已打开 / 有未保存修改**，作为多文档的集中视图
（与 §1“独立项目页为主”一致，且省一块 UI）。文件模式下只有单文档，不需要集中视图。

**已实现**：谱面表“保存状态”列区分 `未打开`（未加载）、`未修改`（已打开且当前清洁、本次载入后尚未保存）、`已保存`（保存成功且当前清洁）、`未保存`（存在会话修改）及 `草稿未存`（当前面板未提交）。未打开与未修改不合并，前者仍用于区分会话是否已加载；编辑撤回初始内容且未保存时回到未修改，撤回已保存点时显示已保存。重新载入重置保存记录，切换已打开文档不重置。
保留“仅已打开”筛选和顶部“已打开 N（未保存 M）”；**点击已在会话中打开的谱面 = 切到该会话，不重新读盘**（保护未保存修改），面板用内存态刷新。
文件夹选择器每次打开显式设置起点：当前仍存在的项目目录 → 上次成功枚举目录（本机偏好，跨重启）→ 用户主目录。取消浏览或失败扫描不改上次成功目录；仅记忆选择器起点，不自动恢复项目。

### 9.3 切音目标 = 项目页勾选集合（唯一真相源）

- 切音的**唯一真相源 = 项目页勾选集合**。
  编辑页显示哪个谱面是**另外选定**的（项目页里打开，或直接打开文件）。
- 因此必须在**切音页显著显示目标**（勾选 N 个 / 当前编辑谱 / 无目标三种文案）+ 项目页顶部
  显示勾选数；目标变化且切音有未保存内容时应提示。否则“看着 A 谱、切音存进 B”极难察觉。
- 文件模式（直接打开文件、没有项目页）下，真相源退化为“当前编辑页打开的谱面”。
- **发起操作时固定目标集合**：预览与提交读同一批 `targets[]`
  （session/路径 + 文档版本），不在执行中途改读 UI 当前选中；应用前校验文档版本，
  避免长时间切音后把旧计划写进已变的内容。用户改项目选择时，应显式重新预览。
- **目标集合的选取方式**：项目页谱面列表每行一个
  checkbox，列头为全选；**勾选非空 = 目标集合 = 勾选项**；**未勾选任何谱面 = 目标退化为
  “当前编辑页打开的谱面”**（也覆盖“新建未保存谱面”这种没有磁盘路径的情况）。
  勾选是**临时集合**，不写盘、不进入谱面内容、不留到下次启动（无项目文件，§9.7）。
- **按文件寻址，不靠活动会话**（审查稿 P0）：目标以路径解析到已打开会话
  （`SessionRegistry::find_by_path`）；未打开的目标按需 `session.load` 进独立会话后再写。
  加载目标**不得改变活动会话**（`session.create` 会顺带激活 → 必须恢复），否则编辑页会跟着跳。

**切音安全实现约定**：

- GUI 使用 `prepareExport → commitExport(planId, filePolicy, wavIdPolicy)`；工具按钮/快捷键触发预检前，显式提交偏移、BPM、细分、起始ID/小节输入框的可见文本，不能依赖Enter或失焦。无效文本阻止导出，不使用旧value；成功导出后的起始ID自动推进不变。预检按需加载真实目标但不编辑谱面、不写 WAV，不改变活动文档。任一目标不可用或混合进制时整批拒绝，避免写出后才发现目标无法铺放。
- 同进制目标按定义、已有 note 引用和 LNOBJ 的占用并集检查 WAV ID。指定起点连续分配遇到占用时，先弹窗选择“从空位分配”（跳过占用，原逻辑）、“覆盖已有 ID”（从指定起点连续分配）或取消；列出冲突 ID 和固定目标，警告旧音符声音/LNOBJ 语义可能改变。不静默覆盖旧定义，覆盖 ID 不等于授权覆盖磁盘音频。两种分配均在同一次预检固定，提交不重新读取 UI；空位不足/连续范围不足时禁用相应选项。成功导出后的 nextStartId 推进规则保持不变。GUI 传入 ID 输入框实际进制；“自动”与实际目标进制不同则要求明确选择并重新确认输入，不能悄悄改变 ID 文本含义。
- 文件重名显示目录、重名列表和固定铺放目标；可选覆盖、续号、取消。覆盖音频可能影响其它引用同名文件的谱面，且不随谱面 undo 恢复；续号必须保留旧文件。目录/符号链接落点和参考音频同名落点拒绝覆盖。
- 确认提交核对一次性计划、会话内容版本/路径、目标集合与磁盘状态；素材/切片/offset 改变使计划失效。写入前再检查最终续号落点；取消不写音频、不编辑谱面。
- 音频只输出一份；各谱面按自身目录生成相对资源路径，未命名谱面使用绝对路径。每谱一个铺放撤销步，不自动保存谱面磁盘文件。
- 磁盘输出和谱面铺放分别报告。文件写入部分失败时明确已写数量，不铺放、不提供包含失败文件的 raw；铺放部分失败时保留成功项并显示失败原因/警告。无跨文件回滚或跨进程输出锁的承诺。

### 9.4 对照布局：拖拽分割，不加 checkbox

中央区使用中央区改成一个内嵌 `SplitView`，`[主视图][handle][副视图]`，
**副视图初始宽度 0**（平时只见一条与现有一致的 4px 分隔条），往左拖即展开；拖到过小自动吸附归零。

### 9.5 独立视图实例与文档绑定

副视图是一个**完整独立的 `ChartView` 实例**（显式文档绑定、自己的列集 / 视口 / 命中测试），而不是“只能画 note 的叠层”。A/B 交换通过文档绑定完成，不复制文档。独立实例为后续 B 编辑支持预留结构，但放开 `editable` 本身不等于 §4.5 跨窗格移动已完成。

**最小框架**：

- `SessionRegistry` 是唯一文档集合：每个 `EditorSession` 持有一份内容、路径、dirty 与 undo 栈；单开 = 集合一项，多开只增加项，不建立第二条“多开模式”路径。
- `DocumentService` 提供可遍历 `instances`、`session(id)` 与 `currentSession`，为每个 ID 持有一个稳定 `ChartSession`。打开已有路径复用实例；新建也是独立新项，不覆盖当前谱面。集合不复制 core 文档。
- `ChartSession.sessionId` 固定到明确文档，时序/资源路径/PCM 缓存归属于该文档桥；同一文档的两个视图共用文档桥，但各有滚动、缩放、选择。空 ID 跟随 active 仅保留给旧桥层调用兼容，生产主路径使用固定 ID 的集合项。
- `ChartView.documentSession` 显式绑定；`editable=false` 屏蔽放置、移动、删除、双击编辑和放置预览，保留查询/选择/导航。副谱不跟随另一文档的全局播放时钟，也不 seek 另一谱音频。
- 当前活动 ID 只决定主编辑目标与全局播放，不能改变固定副桥。现行 `chartSession` context 名称仅是集合当前项的兼容别名；编辑命令注入明确 `session_id`，保存同样按 ID。
- 闭环先用原创的 `testdata/m7-mini-project` 三张四小节小谱：打开A/B、非活动文档编辑、切换、独立撤销、单谱保存重开；再用真实 `ChartView` 验证双视图绑定/视口隔离/只读输入。音频由测试临时生成，不依赖本机素材。真实复杂谱面保留为完整回归，不能被轻量样本替代。
- **可见分割**：中央右边缘保留4px拖条，向左拖出独立只读B；释放时宽度小于120px归零，也可点“×”收起，保留文档与视图。B选择器仅枚举已打开集合（含未命名实例），按稳定ID绑定；名称附实例短ID、未保存星号，悬停可查看路径/完整ID。首次展开优先选非A文档，没有时可参照A；同文档交换禁用。
- 项目页提供“在 A 侧编辑”“在 B 侧对照”两个入口。两个按钮仅分配对应文档，完成后保持在项目页；B入口可直接按需加载未打开谱面或复用已有实例并准备展开B，不激活A、不刷新A草稿、不改变播放来源；加载失败保持原A/B。A入口继续走既有草稿确认，保存/放弃后也留在项目页。双击谱面列表才激活到A并跳转编辑页（仍须先完成草稿确认，取消不跳转）。
- B跟随顶部工具：拖拽工具在空白/音符上拖动均导航视口，选择工具在空白处框选；放置/LN/地雷工具在B仍不可写。视图菜单“隐藏 B 侧次要通道与波形”默认开启，仅显示游玩键/皿，隐藏BPM、STOP、BGA、BGM、踏板及波形总览；同时回收B波形宽度，后台渲染完成也不能绕过隐藏策略。关闭可恢复（BGA/踏板仍遵守更多轨道显示状态，波形仍须渲染就绪）。该开关只改变B显示布局，不改内容或A布局；当前为会话选项，不跨重启保存。
- 主编辑视图无BGM事件时仍提供聚合BGM列，可直接放置首个BGM音符并展开虚拟子通道；仅查看布局不产生dirty或撤销步。
- 交换先经过现有面板草稿保存/放弃/取消流程，再按ID激活B、刷新A的全部面板和播放来源，原A成为只读B；取消/保存失败不交换。交换不复制文档、不重读谱面内容、不改变撤销栈，不自动保存脏谱面（草稿确认选择保存除外）。
- 点击B后，删除/粘贴/撤销重做/选区变换等修改类动作与快捷键禁用，防止误操作A旧选区；回到A或其左右Dock恢复。保存和播放始终指向A。B可独立选择、滚动和缩放，不触发采样试听或主谱seek；即使B选择同一文档也不拥有全局播放时钟。B底部提供自己的悬停信息，属性Dock仍属A。
- 拍位锚点同步见 §4.2，已接入现有独立视图；不实现跨文档复制或新状态管理框架。音符/编排 diff 后置，当前采用下述简单参考叠加，不将重合或换轨自动解释为语义差异。

- **分栏姿态**下两实例完全独立 → §4.1 的列布局难点**在分栏模式不存在**（各用各的列）。
- **叠加姿态**是“同一组件、同一实例”的另一种渲染姿态：要两谱 note 落在同一坐标比较，就**必须**
  共享纵轴基准与列集（按 `Lane` 映射到主视图的列）。所以“完全独立”适用于分栏与交换，
  叠加态本质上是“借用主视图几何”的姿态——这一点无法也不应做成独立实例。

**同屏参考叠加范围**：

- A 标题栏“同屏叠加”进入，共享标题栏“A/B 分栏”返回；保留 B 选择、分栏宽度、拍位锚点和暂停播放头。叠加时 B 独立视图隐藏，不新增输入面。
- B 音符采用主题参考色，在 A 音符和长条下方半透明绘制；完全重合也绘制，通过稍高的端帽保留参考色边缘。支持普通音符、LN 和地雷。显示 B 可开关，透明度可在 10–80% 调整（默认45%）。
- 纵向按 A 的小节长度/方向/缩放，以小节与节内位置投影；不使用 B 的秒数，不自动对齐歌曲偏移。横向按完整 Lane 映射到 A 已有列，不增加 A 列；BGM 展开时按子通道映射，聚合时合并显示。
- B 次要通道沿用隐藏策略；BGA/BPM/STOP 不作为参考音符绘制。无法映射或隐藏的音符显示计数，结构不一致明确提示。
- B 更长时仅扩展查看范围，不扩展 A 可编辑范围，不产生谱面修改；A timing 范围外不显示伪造秒数，也不触发音频定位。
- 仅 A 编辑、选择、保存和播放，B 不命中、不试听；选择 B、交换与关闭继续复用现有文档身份和草稿确认，不复制谱面或改变撤销历史。
- 不计算仅A/仅B/共有分类，不比较资源身份，不做自动偏移、难度判定或混播。
- A/B 的 UI 归属遵守本节现行契约：编辑、属性面板、保存和音频始终属于 A；B 仅保留自己的查看、选择和导航状态。实现前的引用计数与改造成本估算不作为接口约束。

### 9.6 实际制作流程与批量功能强度

本节是用户描述的常规工作流，不代表所有作者的唯一做法：

1. 曲师完成歌曲，切音负责人制作模板：所有 note 先位于 `01` 背景通道，确认播放与 DAW 中一致。
2. 谱师以模板制作不同难度，通常不额外添加空音，主要将部分背景 note 平移到游玩轨。特殊情况包括手写 `#RANDOM` 或为部分难度单独改变歌曲。
3. 制作中或完成多谱后，偶尔需要更新切音/BGA。负责人通常提供原始 BMS 字段，作者手动逐谱复制到受影响文件；批量功能主要减轻这项重复劳动。

**批量功能目标**：支持多选受影响谱面，将负责人提供的字段或切音/资源绑定结果应用到这些目标；目标可预览、每谱可撤销、修改后统一保存。多选目标不能被实现成仅“当前活动谱面”。

**无需扩展为自动重切迁移系统**：首期不要求自动识别旧新切片对应关系、记录稳定切片血缘、处理任意拆片/并片后自动保住旧编排，也不要求强制版本化资源文件。负责人提供的更新内容是输入，不由软件猜测意图。

自定义片段按 §3.2 实现：字段/定义更新与新增note铺放分开，保存遵循正常codec顺序，不按原文位置插入；显式数据组替换在预览列出小节/源通道和范围，不能把“应用切音结果”默认解释为再次追加整份背景模板。控制块与结构指令仍有限制，风险警告不表示已支持任意内容。

常规流程下，多难度对比主要服务于**同一音乐素材如何分配到背景与游玩轨，以及游玩轨的编排差异**。比较总 note 数不能单独代表难度差异；同一个音乐事件在两谱里换轨是有意义的编排变化，不应仅当成无关的删除与新增。具体差异分类仍属于对照功能细化。

实现需要保证：
显式文档绑定（视图按文档引用，不依赖全局“活动会话”）、视图实例绑定、同路径资源更新后的缓存失效与
后台结果丢弃、切音目标集合在执行期固定（§9.3）；自动切片迁移与完整资源版本系统不是因此追加的要求。

### 9.7 其它决定

- `#RANDOM/#IF`：**只加一条 lint 警告**（提示该谱不要做保存操作），不做“不确定”状态、不做并集索引
  ——正确解析要改 core 且改编辑页工作区逻辑（现为“非块内容 + raw 兜底”，属 M9）。建议项目页也显示该徽标。
- **不引入“项目文件”**，保持无状态（无导出操作）。已知边界：项目级临时状态（选中项/同步开关/筛选）
  不持久化，刷新 = 重新扫描；崩溃时多张谱的未保存修改无法恢复。
  另注：应用**已经**会写 `<谱面>.bak`（每次编辑的崩溃备份），故“无状态”指不引入项目级描述文件，
  不是“磁盘上不产生附加文件”。
- 资源状态维度按 §2 展开（实际缺失 / 扩展名回退 / 大小写差异 / 项目外 / 已定义未使用），
  其中“已定义未使用”首屏显示**待统计**、后台补齐（复用现有 `collect_sample_usage`：编辑页采样面板
  已有每谱 `refs` 计数与“未引用”分组）。
- 阶段 2 的对照视图与阶段 2.5 的叠加共用文档接入、B 选择与结构提示；叠加借用 A 的绘制几何，不引入三态判定或语义 diff 内核。旧草案的“叠加播放”（两谱同时出声）已确定不做。

### 9.8 可选本地谱面快照

- 面向不熟悉 Git 的作者，仅呈现“历史快照”：时间戳 + 用户备注（可空），纯本地、默认关闭，不要求学习暂存/分支/远端操作。
- 主动创建入口；关闭程序时可选择“保存并创建快照”。保存更新当前文件，快照保留历史；无内容变化不重复记录。它不替代未保存确认、撤销或崩溃恢复。
- 首版范围为已保存谱面文件，查看历史和恢复为副本；是否包含媒体必须明确标识。仅谱面快照不承诺恢复被覆盖的 WAV，也不称完整项目备份。
- **极简流程**：文件 → 谱面历史 → 启用（默认关闭）；已命名谱面点击“保存并创建快照”，备注可空。保存复用现有元信息草稿、PMS 后缀确认与失败处理；取消不创建快照，快照失败不回滚已成功的文件保存。未命名谱面先走正常另存为。
- **项目页入口**：右侧提供“资源 / 谱面历史”页签，复用菜单弹窗的历史管理面板。历史跟随左侧选中谱面；未选中时显示当前 A。查看未打开谱面的历史/恢复副本不打开或切换文档；只有所选目标为已命名的当前 A 时可“保存并创建快照”，其它目标先“在 A 中编辑”。菜单入口保留；嵌入页签的保存完成不另弹窗口。
- **首版后端简化**：使用应用专属本地数据目录中的独立快照文件，不采用 Git；不要求安装、账号、配置或学习版本管理，不触碰用户已有仓库及暂存区。界面不暴露提交/分支等概念。路径隔离、完整字节校验、原子写与跨进程锁由应用负责。
- **恢复保护**：按选定历史在原谱面目录生成唯一命名的新副本，保留原后缀与相对媒体查找基准；排他创建，绝不覆盖原文件、不切换或重载当前编辑会话。界面给出副本路径，用户可正常打开对比。不恢复历史媒体。
- **退出选项**：另设“退出时为已保存谱面创建快照”，默认关闭；仅处理干净、已命名文档，放弃的未保存更改不记录。失败阻止本次退出，可重试，或明确关闭此可选项后退出。关闭功能不会删除已有历史。
- 存储位置为 `QStandardPaths::AppLocalDataLocation/chart-history-v1`，按规范化谱面路径分组；移动或另存为路径后属于另一组历史。单谱面最大 16 MiB、每组最多 1000 条，达到限制明确报错，不静默删除历史。历史不随歌曲文件夹自动迁移，也不替代异机备份。
- **性能边界**：查看及手动创建后刷新列表会逐条校验完整历史载荷；大历史需等待操作结束，期间不能退出。可选退出批次目前同步执行，大量谱面或慢速目录可能阻塞界面；尚不承诺大规模/网络目录的响应性。
- 不做账号、远端同步、分支界面、自动合并或 Git LFS。先完成当前安全/拖动改进与阶段②/②.5，再于阶段③批量修改之前落实快照首版。
