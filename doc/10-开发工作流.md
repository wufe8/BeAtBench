# 开发工作流（分支 / 门禁 / 发布 / 备份）

> 面向单人开发的轻量流程：**目标是少一次「事后补 commit」**。
> 相关脚本：`scripts/check.sh`、`scripts/check-version.sh`、`scripts/release.sh`、`scripts/backup.sh`、`.githooks/pre-push`。

## 1. 分支

| 分支 | 用途 | 规则 |
|---|---|---|
| `dev` | **日常开发唯一落点** | 随便提交；推 origin 做备份；不要求每次绿 |
| `master` | 发布线 | **只通过 PR 从 `dev` 合入**；tag 只在 master 上打 |
| `feat/*`（可选） | 大改动的隔离 | 从 `dev` 切，改完合回 `dev` |

流程：`dev` 上开发 → 自测（`scripts/check.sh`）→ 开 PR `dev → master` → 合入 → 在 master 上打 tag 发版。

## 2. 日常门禁（替代「手动 CI」）

```bash
scripts/check.sh                 # 全量：配置 + 构建 + ctest + GUI 无头冒烟（含 QML 作用域告警断言）
scripts/check.sh --quick         # 同上，但跳过真实谱面测试（BB_SKIP_REAL=1，秒级）
scripts/check.sh --core          # 只走无 Qt 路径（core/CLI/audio + 单测）
```

- 结果落点：截图与 QML 日志在 `local/tmp/check/`，不污染仓库根。
- 装了 pre-push hook 后，`git push` 会自动跑 `--quick`；推 `v*` tag 时额外跑版本一致性检查。
  安装一次即可：`git config core.hooksPath .githooks`；赶时间 `SKIP_CHECK=1 git push`。
- 预设（`CMakePresets.json`）：`cmake --preset core|gui|check`；本机路径在 `CMakeUserPresets.json`（gitignore）里。
- CI（`.github/workflows/ci.yml`）是同一套检查的远端副本：**本地快档 + CI 全量**，两者不重复造轮子。

## 3. 发布（tag → 自动出包）

```bash
# 1) 改版本：CMakeLists.txt 的 project(... VERSION x.y.z)
# 2) 写 CHANGELOG.md 的 “## [x.y.z] - 日期” 小节
# 3) 更新 README 的下载名（beatbench-vx.y.z-win64.zip）
scripts/check-version.sh vx.y.z      # 本地先自查（--strict 时警告也算失败）
scripts/release.sh                    # 可选：本地先完整打一次包验证
git tag vx.y.z && git push origin vx.y.z   # → release.yml 自动构建 + 打包 + 建 Release
```

- **版本单一来源**：tag 为准；`scripts/check-version.sh` 强制 CMakeLists / CHANGELOG / README 三处一致，
  顺带把「Qt 版本示例过期」「其它文档残留旧发行物名」列为警告（`--strict` 变失败）。
- **打包只有一个实现**：`scripts/package-release.sh`；本地（`release.sh`）与 CI（`release.yml`）都调它。
- 发布说明 = CHANGELOG 对应段落（`--print-notes`）+ 构建环境（Qt/编译器/CMake 版本，写进 Release 便于复现）。
- CI 回归用 Qt 6.11.2、发布包钉 6.11.1：这个差异写在 Release notes 里，别让它变成隐性知识。

## 4. 备份（单机单盘的两道保险）

```bash
scripts/backup.sh            # 提交 local/ 未落盘改动 + 给主仓库和 local/ 各打一个 git bundle 到 OneDrive
scripts/backup.sh --push     # 额外 push 有远程的仓库
```

- 默认备份目录：`~/OneDrive/BeAtBench-backup`（找不到云盘就落到 `~/BeAtBench-backup`），保留最近 10 份。
- 建议再加一个**私有远程**给 `local/`（笔记/截图/测试谱面目前只在本地）：
  `git -C local remote add origin git@github.com:<你>/BeAtBench-local.git && git -C local push -u origin master`
- 建议用系统计划任务每天跑一次 `backup.sh`（Windows 任务计划程序 / cron）。

## 5. 与在途 PR 的关系（重要）

本文件与相关脚本是在 PR #1/#2/#3 **尚未合并**时添加的，刻意避开它们改动的内容：

- 不碰 `.github/workflows/ci.yml`（PR #2 新增）、`CMakeLists.txt`、`app/**`、`audio/**`、`tests/**`
- 不碰 `README.md` / `AGENTS.md` / `doc/04`（PR #3 改动）

**在 PR #1 合并前，门禁会红两次，属预期：**

1. MinGW/GCC 路径构建失败：`tests/waveform_pyramid_test.cpp` 缺 `<cmath>`（`std::sin`），PR #1 补头后即绿。
2. 若构建通过，GUI 冒烟的 QML 作用域断言会报 `SplitView: attached properties must be accessed...`（`EditPage.qml`/`SlicePage.qml`），PR #1 改用 `SplitHandle` 后即绿。
   注意：PR #1 现写法（子对象里裸写 `SplitHandle.hovered`）只消告警、悬停高亮仍不生效，见
   `local/doc/14-PR1-3-跨平台CI审查.md`；建议把它一并改掉。

这段时间要 push 就用 `SKIP_CHECK=1 git push`，或在 PR #1 合并后 `git checkout dev && git merge master` 让 dev 跟上。

PR 合并后需要补的两件事：

1. `AGENTS.md` §5/§6 加一行指向本文件（分支模型 + `scripts/check.sh`），并修正构建速查的 MSVC 口径
   （多配置下 `ctest` 必须带 `-C Debug`，否则全部 `Not Run`）。
2. `ci.yml` 与 `release.yml` 里相同的 aqt 临时钉（`aqtinstall @ ...@076e1659`）在 aqt 3.4.0 发布后一起收回为版本钉。
