## 1. 目标与边界

一个项目对应**一首歌的文件夹**，包含多个难度/模式的谱面与共享音频、BGA、图片等文件，允许内部子目录。子目录属于这首歌，不由扫描自动转成多曲合集或数据库。

先解决：看清项目有哪些谱面与资源、资源被哪些谱面引用、缺失在哪里、如何导入和重定位。然后支持谱面对比，尤其是编辑时左右参照另一张谱面。

### 已确认的范围

- 项目以文件夹为入口，不要求先创建专有项目文件。
- **独立项目页为主，资源表为主、目录树辅助**；当前编辑页的采样绑定与文件手动管理已经可以闭环，新增项目侧栏不紧迫。
- 导入项目外资源时**复制进项目**；绑定到谱面另行选择，不因复制自动分配 WAV/BMP ID。
- 缺失重定位先列全部受影响引用，用户勾选后应用。
- 引用修改成为各谱面独立的未保存修改，支持逐谱撤销，之后统一保存。
- 后续编辑 A/B 左右各显示一张谱面，宽度可调，可交换，可选择同步滚动和位置；首期允许左侧编辑、右侧只读。
- 首期 A/B 播放左侧谱面。

### 后置范围

- 普通磁盘文件的移动、重命名、删除等，先继续使用系统文件管理器。资源复制导入和谱面引用重定位属于当前范围。
- 打包：BMS 文件夹目前可以手动压缩，不作为资源管理或对比的先期验收条件。
- 多曲合集工作区、数据库、专有项目/工作区持久化格式。
- 双侧均可编辑；实现后可考虑由最后选中的一侧决定实际播放来源。
- 广泛批量元信息、编码转换、note 变换等，保留为后续候选，未确认具体交付顺序。
  （**叠加姿态**已不在后置范围：排入 §9.1 阶段 2.5，呈现形态见 §9.7；仅具体差异指标口径仍开放，见 §8。）

### 架构边界

- Project 做索引与分析，不把多个谱面合并成一个文档。每张谱面独立 `EditorSession`、undo、脏标记和保存。
- 不做改 A 自动改 B 的实时内容联动；资源重定位是显式选择范围的操作。
- core 格式无关、零 Qt，命令作为操作入口；GUI 展示与确认，CLI 可复用查询能力。
- `#WAV` 占用查询属于 core/project 与项目展示，不放进 `SliceWorkspace`。
- M7 不承担 SliceWorkspace 拆分、i18n、试玩判定或 L2 布局皮肤。

## 2. 项目与资源的对象区分

| 对象 | 作用 |
|---|---|
| 项目根目录 | 一首歌的文件范围，允许子目录 |
| 谱面条目 | 路径、格式、元信息、诊断、按需统计；打开后对应独立文档会话 |
| 磁盘资源 | 项目中的实际文件，也能显示谱面引用但缺失或位于项目外的目标 |
| 谱面内定义 | 某张谱面的 WAV/BMP ID 与声明路径；不同谱面可以用不同 ID 指向同文件 |
| 引用关系 | 文件 ← 谱面 / 定义 ID / 头部字段；有需要时再补事件使用位置 |

**项目资源表以文件为单位；现有采样面板以当前谱面的槽位为单位。**不能把“没有 note 使用某个 WAV 定义”和“磁盘文件没有任何谱面引用”混为一谈。

**资源表收录范围（2026-10-10 定）**：识别**当前文件夹内的全部相关文件**——谱面（`.bms/.bme/.bml/.pms`）、
音频、图片、视频；用户不需要手动把文件拖进来。**排除应用生成物**（`<谱面>.bak` 崩溃备份、切音导出目录）
与其它类型（`.txt` 等），否则"未被引用"的结论会被自己的备份文件污染。
"磁盘文件没有任何谱面引用"因此成为**可见信息**（DAW 漏导出、BGA 换版这类修复场景正需要它）。

**排除只作用于目录枚举，不作用于已解析引用**（正确性要求，非偏好）：任何被谱面引用到的文件都必须出现在
资源表里——切音导出目录中的成品切片尤其如此，它正是资源更新（§9.6）的操作对象。备份/缓存可隐藏；
已绑定但无引用的旧切片可标注来源、默认折叠，但不能仅凭所在目录名判定为无关。资源表口径为
"当前已解析引用"，不声称穷尽 `#RANDOM/#IF` 全部分支（§9.7）。

资源查询应区分：

- 项目内实际文件与谱面声明的目标；声明目标不存在时仍应有缺失条目。
- 被哪些谱面定义或封面字段引用。
- 已定义，但没有已知事件使用。
- 磁盘文件没有已知谱面引用；这类文件可能是创作源文件或附带文档，不能因此推定应删除。
- 文件位置、实际可用性和路径兼容提示是不同信息。缺失、外部路径、扩展名替代、大小写差异的具体显示与匹配规则见 §8 待补。

模型可沿用 `Project{root_path,charts,resources}`、`ChartRef`、`ResourceRef`、展示分组。ResourceRef 需保留引用来源，不能只用一个计数代替关系。准确字段与命令参数在实现前细化。

**已落地的 core 形状**（2026-10-11，阶段①）：`ChartRef{path,format,mode,元信息,统计,errors/warnings,missing_resources,random_blocks,parsed,read_error}`；
`ResourceRef{path,declared,kind,on_disk,outside,ext_fallback,case_differs,total_refs,uses[]}`，
`uses[]` = `{chart, source(define/header), kind, id, field, refs}`（保留出处，可回答"同一文件被哪些谱的哪个 ID 引用"）。
`Project{root,truncated,charts,resources,warnings}` 带 `missing_resources()` / `unreferenced_resources()` / `find_chart` / `find_resource`。
两段式：`scan(parse=false)` 只枚举（实测 50 谱包 ≈0.1s，秒出表格），`scan_parse` 后台补元信息/统计/引用
（同一包 ≈4.7s，成本≈解析器本身；定义表满 1296 槽时资源解析已改走目录索引缓存，不再逐候选 stat）。

扫描目标：不加载/解码音频即可列谱面和资源；基础信息尽早出现，完整统计按需后台补。子目录遍历、取消、性能限制与刷新应围绕单曲项目设计，不能把已有扫描开头的默认限额当成产品定案。

## 3. 第一阶段：资源管理

### 3.1 打开与浏览

- 文件菜单打开歌曲文件夹，进入独立项目页。
- 谱面列表与资源表提供独立入口；目录树辅助定位。
- 资源表可查看路径、类型、可用状态和引用谱面；选中文件查看具体谱面 / ID / 字段。
- 打开谱面仍使用现有文档会话；浏览资源详情不要求打开谱面音频。
- 当前编辑页的元信息、采样、lint、BGA、属性与时间轴保持单谱职责。

### 3.2 导入

- 从项目外选择/拖入资源，复制进项目。
- 复制落点及撞名处理需给用户可理解的结果；不得默认覆盖。
- “文件加入项目”与“分配谱面 ID 并绑定”分两步。
- 绑定时目标谱面、已有绑定及 ID 分配方式需显式确定；不默认对全项目所有谱面添加定义。
- 导入后的复制文件与谱面 undo 是不同对象；磁盘复制如何处理取消/失败见 §8。

### 3.3 缺失重定位

- 从缺失条目发起查找替代文件。
- 展示原路径 → 新路径，以及全部受影响谱面和 ID / 字段。
- 用户勾选应用范围后修改引用，不静默改全部谱面。
- 每张目标谱面有独立撤销步；不直接覆写其磁盘文件。
- 修改后标为未保存，可以检查、撤销，再统一保存。
- 保存与关闭流程需汇总项目内未保存谱面；保留已有确认纪律。

### 3.4 第一阶段验收

- 同歌多谱面与内部子目录正确列出，资源浏览无需音频解码。
- 同一文件被多谱不同 ID 使用时，详情能准确列出引用关系。
- “已定义未使用”和“磁盘无已知引用”正确区分。
- 导入复制完成后，不自动改变任何谱面绑定。
- 重定位可以只改勾选谱面；各谱可独立撤销；未保存前磁盘谱面保持原内容。
- 统一保存与关闭确认不会遗漏被资源修复修改的谱面。

## 4. 第二阶段：谱面对比与编辑 A/B

### 4.1 编辑布局

- 左右各显示一张谱面，中间分隔线可调整宽度。
- 提供交换左右功能。
- 首期左侧可编辑，右侧只读；交换后原右谱进入左侧成为编辑对象。
- 当前采样、属性、编辑命令、撤销与保存保持明确的单谱归属，不能因右侧点击自动修改错误文档。
- 两张谱面的文档状态独立，交换只是显示角色变化。
- 此 A/B 双谱布局与现有播放 A-B 循环点是不同功能，命名与入口需区分。

### 4.2 视口同步

同步的是**视口**，沿用现有编辑器滚动与定位逻辑。

- 提供是否同步滚动 / 位置的开关。
- 原有会导致视口改变的入口，对参与同步的已开启谱面视图应用相应操作；关闭同步时各视图保持独立。
- 开发时需盘点滚轮、拖动、跳转、播放跟随、seek、缩放等现有入口，统一处理，避免只有滚轮同步而其他入口漏掉。
- 本目标没有新增“按小节 / 按秒对齐谱面”的用户选项，没有修改谱面事件或 timing 数据的要求。
- 不应把同步实现成某个控件事件中临时复制另一视图像素偏移；实际复用哪个现有视口参数，需要实现前核对当前逻辑。

### 4.3 播放与后续编辑

- **只播放主谱**（2026-10-10 定）：不做两谱同时出声的混合播放——合并时间轴在结构不一致时没有定义，
  且它最贵。副谱只用于"看"，不参与发声。同步视口按现有播放跟随规则参与更新。
- 右侧只读不意味着加载另一套 BGM 混播。
- 后续双侧可编辑时，可考虑以最后选中的一侧决定实际播放来源，具体交互届时细化。

### 4.4 对比分析候选

原草案的统计（note/LN/密度/BPM）、结构（元信息、定义表、timing）与叠加 diff 保留为候选能力。用户已确认“资源管理之后做谱面对比”，并明确编辑双谱布局与**叠加姿态**（已排入 §9.1 阶段 2.5，与分栏共用内核，见 §9.7）；**具体分析指标与统计口径尚未确认**，不把旧草案的全部指标作为首期必做。“叠加播放”（两谱同时出声）已确定不做（§4.3）。

验收重点：两谱能同时显示，宽度可调、可交换；右侧内容不可编辑；所有视口变化入口遵守同步开关；左侧命令只改左谱；播放来源明确。

## 9. 第二轮定案与分期（2026-10-10，Windows 开发机会话）

> 本节记录第一稿（同日）之后新确认的决定。过程记录见 `local/doc/17-M7决策补充-2026-10-10.md`。

### 9.1 分期与顺序（**开发顺序以此为准**）

用户指出最大痛点是**同一首歌不同难度的对比**；同时指出结构性依赖：
"要先有项目页能开多个文件，才能指定副窗格显示哪个谱面"。核对后确认**两处**依赖都挂在项目页上
（副窗格的谱面选择器、切音目标）。故项目页先，但把"只读索引"与"磁盘写"拆开，让最大痛点不必等
高风险工作：

| 期 | 内容 | 风险 |
|---|---|---|
| **1. 项目页（只读索引版）** | `project.scan` + 项目页（谱面表 + **已打开/未保存标注** / 资源表 / 筛选）+ 选中→编辑页打开 + **勾选→切音目标集合** + 多文件会话 | 低（纯读，不写盘）**——已可运行**；目标集合已按路径寻址并对"导出后铺放"生效（多目标每谱一个撤销步）；导入 / 绑定更新 / 重定位仍属阶段③ |
| **2. 对照视图** | 多实例化 + 拖拽分割 + 副窗格只读 + 视口同步 + 统计/结构 diff（纯 core 命令） | 中 |
| **2.5 叠加姿态** | 副窗格内切「分栏 / 叠加」：三态（仅A/仅B/都有）+ 双色 + 筛选 | 中 |
| **3. 资源导入 / 多选绑定更新 / 缺失重定位** | 复制进项目、绑定分两步；多选应用负责人提供的字段或切音绑定结果（范围见 §9.6）；逐谱 undo + 统一保存 | 涉及文件复制时需处理磁盘失败；纯绑定更新以文档命令执行 |
| **4. 其它批量 / 打包** | 后置；不包含上期已明确的多选资源绑定更新 | — |

### 9.2 项目页兼任"已打开文档"视图

不引入顶部/底部标签条：项目页列出谱面时就标注**已打开 / 有未保存修改**，作为多文档的集中视图
（与 §1"独立项目页为主"一致，且省一块 UI）。文件模式下只有单文档，不需要集中视图。

**已实现（2026-10-15）**：谱面表「保存状态」列区分 `未打开`（未加载）、`未修改`（已打开且当前清洁、本次载入后尚未保存）、`已保存`（保存成功且当前清洁）、`未保存`（存在会话修改）及 `草稿未存`（当前面板未提交）。未打开与未修改不合并，前者仍用于区分会话是否已加载；编辑撤回初始内容且未保存时回到未修改，撤回已保存点时显示已保存。重新载入重置保存记录，切换已打开文档不重置。
保留「仅已打开」筛选和顶部「已打开 N（未保存 M）」；**点击已在会话中打开的谱面 = 切到该会话，不重新读盘**（保护未保存修改），面板用内存态刷新。

### 9.3 切音目标 = 项目页勾选集合（唯一真相源）

- 切音的**唯一真相源 = 项目页勾选集合**（2026-10-11 由"单选选中项"改为**多选 checkbox**，
  用户的理由：实际需求本就是"一次改好几张受影响谱面"，而单选看不出"哪些是目标"）。
  编辑页显示哪个谱面是**另外选定**的（项目页里打开，或直接打开文件）。
- 因此必须在**切音页显著显示目标**（勾选 N 个 / 当前编辑谱 / 无目标三种文案）+ 项目页顶部
  显示勾选数；目标变化且切音有未保存内容时应提示。否则"看着 A 谱、切音存进 B"极难察觉。
- 文件模式（直接打开文件、没有项目页）下，真相源退化为"当前编辑页打开的谱面"。
- **发起操作时固定目标集合**（2026-10-10 架构审查采纳）：预览与提交读同一批 `targets[]`
  （session/路径 + 文档版本），不在执行中途改读 UI 当前选中；应用前校验文档版本，
  避免长时间切音后把旧计划写进已变的内容。用户改项目选择时，应显式重新预览。
- **目标集合的选取方式（2026-10-11 定，替换原"单选当前目标"）**：项目页谱面列表每行一个
  checkbox，列头为全选；**勾选非空 = 目标集合 = 勾选项**；**未勾选任何谱面 = 目标退化为
  "当前编辑页打开的谱面"**（也覆盖"新建未保存谱面"这种没有磁盘路径的情况）。
  勾选是**临时集合**，不写盘、不进入谱面内容、不留到下次启动（无项目文件，§9.7）。
- **按文件寻址，不靠活动会话**（审查稿 P0）：目标以路径解析到已打开会话
  （`SessionRegistry::find_by_path`）；未打开的目标按需 `session.load` 进独立会话后再写。
  加载目标**不得改变活动会话**（`session.create` 会顺带激活 → 必须恢复），否则编辑页会跟着跳。

### 9.4 对照布局：拖拽分割，不加 checkbox

参考旧编辑器 iBMS BMCreator Delta 3.0.5（`local/screenshot/ref/4d290f7c-….png`）：其视图菜单有
「左分割器/右分割器」，**直接拖边缘出现左/中/右三窗格**。用户评价（采纳）：**拖分割线比新增
checkbox 更无感**。做法：中央区改成一个内嵌 `SplitView`，`[主视图][handle][副视图]`，
**副视图初始宽度 0**（平时只见一条与现有一致的 4px 分隔条），往左拖即展开；拖到过小自动吸附归零。

### 9.5 架构取向：**多个独立实例**（用户提议，采纳）

副视图应当是一个**完整独立的 `ChartView` 实例**（自己的 session / timing / 列集 / 视口 /
命中测试），而不是"只能画 note 的叠层"。收益：**A/B 交换**成为交换两个实例的 session 绑定；
**将来开放副谱可编辑**也只是放开 `editable`；两者都不需要重写渲染。

- **分栏姿态**下两实例完全独立 → §4.1 的列布局难点**在分栏模式不存在**（各用各的列）。
- **叠加姿态**是"同一组件、同一实例"的另一种渲染姿态：要两谱 note 落在同一坐标比较，就**必须**
  共享纵轴基准与列集（按 `Lane` 映射到主视图的列）。所以"完全独立"适用于分栏与交换，
  叠加态本质上是"借用主视图几何"的姿态——这一点无法也不应做成独立实例。
- 成本实测（比预期低）：`Main.qml` **零改动**（它不直接引用 `chartView`，全走 `editPage.` 门面：
  `locateChartView()`/`zoomPercent`/`hoverText`/`playheadPosText`/`probeLocal`/`clickLocal`…）；
  改动集中在 `EditPage.qml` 的 24 处 `chartView` 引用——**几乎全是薄委托**
  （`if (chartView) chartView.X(...)`）与只读镜像属性，改为指向"当前活动窗格"即可；
  真正要做的设计是**哪些 UI 跟活动窗格、哪些按窗格各自独立**（工具栏/左右 dock/波形条/状态栏读数）。

### 9.6 实际制作流程与批量功能强度（2026-10-10 用户补充）

本节是用户描述的常规工作流，不代表所有作者的唯一做法：

1. 曲师完成歌曲，切音负责人制作模板：所有 note 先位于 `01` 背景通道，确认播放与 DAW 中一致。
2. 谱师以模板制作不同难度，通常不额外添加空音，主要将部分背景 note 平移到游玩轨。特殊情况包括手写 `#RANDOM` 或为部分难度单独改变歌曲。
3. 制作中或完成多谱后，偶尔需要更新切音/BGA。负责人通常提供原始 BMS 字段，作者手动逐谱复制到受影响文件；批量功能主要减轻这项重复劳动。

**批量功能目标**：支持多选受影响谱面，将负责人提供的字段或切音/资源绑定结果应用到这些目标；目标可预览、每谱可撤销、修改后统一保存。多选目标不能被实现成仅“当前活动谱面”。

**无需扩展为自动重切迁移系统**：首期不要求自动识别旧新切片对应关系、记录稳定切片血缘、处理任意拆片/并片后自动保住旧编排，也不要求强制版本化资源文件。负责人提供的更新内容是输入，不由软件猜测意图。

应用字段与现有编排的具体处理规则仍需在批量功能设计时明确：资源定义更新与新增 note 铺放应分开；不能把“应用切音结果”默认解释为再次追加整份背景模板。原始字段包含数据行、定义冲突或控制块时的支持范围，不能视为已全部批准。

常规流程下，多难度对比主要服务于**同一音乐素材如何分配到背景与游玩轨，以及游玩轨的编排差异**。比较总 note 数不能单独代表难度差异；同一个音乐事件在两谱里换轨是有意义的编排变化，不应仅当成无关的删除与新增。具体差异分类仍属于对照功能细化。

此前架构审查提出的实现正确性问题仍适用（依据：`local/doc/M7-双痛点反向设计审查-2026-10-10.md`）：
显式文档绑定（视图按文档引用，不依赖全局"活动会话"）、视图实例绑定、同路径资源更新后的缓存失效与
后台结果丢弃、切音目标集合在执行期固定（§9.3）；自动切片迁移与完整资源版本系统不是因此追加的要求。

### 9.7 其它决定

- `#RANDOM/#IF`：**只加一条 lint 警告**（提示该谱不要做保存操作），不做"不确定"状态、不做并集索引
  ——正确解析要改 core 且改编辑页工作区逻辑（现为"非块内容 + raw 兜底"，属 M9）。建议项目页也显示该徽标。
- **不引入"项目文件"**，保持无状态（无导出操作）。已知边界：项目级临时状态（选中项/同步开关/筛选）
  不持久化，刷新 = 重新扫描；崩溃时多张谱的未保存修改无法恢复。
  另注：应用**已经**会写 `<谱面>.bak`（每次编辑的崩溃备份），故"无状态"指不引入项目级描述文件，
  不是"磁盘上不产生附加文件"。
- 资源状态维度按 §2 展开（实际缺失 / 扩展名回退 / 大小写差异 / 项目外 / 已定义未使用），
  其中"已定义未使用"首屏显示**待统计**、后台补齐（复用现有 `collect_sample_usage`：编辑页采样面板
  已有每谱 `refs` 计数与"未引用"分组）。
- 阶段 2 的对照视图与阶段 2.5 的叠加**共用同一套内核**（副谱接入 + 三态判定 + 结构一致性检查），
  差别只在呈现。旧草案的"叠加播放"（两谱同时出声）已确定不做。
