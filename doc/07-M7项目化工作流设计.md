# M7 设计：项目化工作流（Project Workspace）

> 状态：**未实现的设计草案**。以下项目模型、`project.*` 命令、界面与验收目标均为规划，不是当前可用能力；排期权威见 `doc/04` §7。
> 关联：`doc/02`（模型/命令架构）、`doc/06` §3（JSON 协议）、`doc/08`（GUI 分层）。

## 1. 背景与目标

### 要解决的问题

BMS/音游的天然单位不是“一个 .bms 文件”，而是**一首歌的文件夹**：一首歌通常带多个谱面
（7K NORMAL/HYPER/ANOTHER、14K、PMS、DP…）+ 一套共享音频/BGA。当前编辑器只能单文件打开，
作者被迫做重复劳动：

- 反复开关文件才能看清“这首歌到底有哪几个难度”；
- 手工对比难度曲线/密度（ANOTHER 是否真的比 HYPER 难）；
- 同一首歌的公共字段（ARTIST/GENRE/STAGEFILE/`#WAV` 文件名）改 N 遍；
- 打包前手工核对缺失采样/大小写/编码。

### M7 目标（里程碑结束时）

1. 打开文件夹 → 列出项目内所有谱面与资源（含缺失徽标）；
2. 一次打开多个谱面并切换（复用现有会话/缓存）；
3. 任选两个谱面做对比（统计 / 结构 / 叠加三层）；
4. 对多选谱面做**安全**批量操作（先预览、可逐谱撤销）；
5. 一键打包 zip 并校验引用完整性。

### 非目标（明确不做）

- **不把多谱面合并成一个文档**：每个谱面仍是独立 `EditorSession`（各自 undo/保存）。
- 不做跨谱面实时联动编辑（改 A 自动改 B）——那是另一个设计。
- 不在 M7 拆 `SliceWorkspace`（M8）；M7 的 `#WAV` 占用走 core 查询，**不进 SliceWorkspace**。
- 不做 i18n / 试玩判定 / L2 皮肤（M10+）。

## 2. 领域模型（core 新增 `project/`，格式无关、零 Qt）

| 类型 | 关键字段 | 说明 |
|---|---|---|
| `Project` | `root_path`, `charts[]`, `resources[]` | 一个文件夹 = 一个项目 |
| `ChartRef` | `path`, `format`, `meta{title,artist,difficulty,playlevel,player,mode}`, `stats{notes,ln,mines,bpm_min,bpm_max,duration}`, `size/mtime` | 谱面条目 |
| `ResourceRef` | `path`, `kind(wav/ogg/mp3/bmp/jpg/mpg)`, `referenced_by[]`, `exists` | 资源条目 |
| `ChartGroup` | `key(difficulty/mode/player)`, `charts[]` | 分组展示用 |

原则：

- Project 只做**索引与分析**，不拥有文档；打开谱面仍走 `session.load`。
- 扫描先只读头部（`#TITLE`/`#WAV`/`#BPM`/`#PLAYLEVEL` 等），主数据按需后台解析（大包不卡 UI）。
- 识别：扩展名 `.bms/.bme/.bml/.pms` + 头部有效性；编码沿用现有检测。

## 3. 命令（core/command，headless 可测）

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `project.scan` | `path` | manifest | 扫描文件夹 → Project 清单 |
| `project.verify` | `path` | report | 缺失 / 未引用 / 大小写 / 编码问题 |
| `project.compare` | `a`, `b`, `options` | diff | 结构化对比（统计 / 元信息 / `#WAV` / timing / note 分布） |
| `project.batch` | `targets[]`, `commands[]`, `dry_run` | results[] | 批量操作；`dry_run` 不写盘 |
| `project.pack` | `path`, `out`, `strict` | report | zip 打包 + 校验 |

> `project.compare` / `project.batch` 必须是纯 core 能力（CLI 可直接用），GUI 只做展示与确认。

## 4. 功能分期

### M7.1 文件夹导入 + 项目面板（基础，必做）

- File→打开文件夹；后台扫描 + 进度；项目面板列谱面与资源。
- 谱面列表列：文件、难度、等级、模式、note/LN 数、BPM 范围、**缺失资源徽标**。
- 资源清单：缺失 / 未引用 / 被哪些谱面引用。
- 验收：真实歌曲文件夹正确列出多谱面与缺失资源；**不加载音频**即可完成。

### M7.2 多谱面会话（必做）

- 项目面板勾选 1..N → 标签页打开（复用 `SessionRegistry`）。
- 共享采样解码缓存（`SampleCache` 按路径复用）。
- 验收：一次开 3 个难度、切换不丢状态；同一 wav 只解码一次。

### M7.3 谱面对比（核心亮点）

- **统计对比**：总 note/LN/地雷、分轨密度、BPM 范围、时长、最高密度区间、最长连打。
- **结构对比**：元信息字段级 diff、`#WAV`/`#BMP` 定义表 diff、timing 事件 diff。
- **叠加视图**：同一时间轴画两谱 note（A/B 双色），筛“仅 A / 仅 B / 都有”；共享播放头，
  A/B 切换或叠加播放（可静音其一）。
- 只读，不产生编辑。
- 验收：同歌两难度对比正确；叠加视图时间对齐；`project.compare` 有单测。

### M7.4 多谱面批量操作（高价值）

- 批量元信息（ARTIST/GENRE/STAGEFILE/BANNER/`#PATH_WAV`）。
- 采样定义重命名/重定位、缺失资源批量重定位、编码/换行统一。
- 破坏性操作（BPM/STOP 缩放等）放最后，且必须预览。
- 事务：`dry_run` 先出 diff；每个谱面一个独立 undo 步；逐谱报告 applied/failed。
- 验收：批量改 3 个谱面的 GENRE 成功且各自可撤销；`dry_run` 不写盘。

### M7.5 项目打包与校验

- `project.pack`：标准目录结构 zip + 引用完整性（缺失/`#PATH_WAV`/大小写/编码）+ 未引用文件报告。
- `project.verify`：只报告，不写盘。
- 实现为独立 `ArchiveExporter`（core/cli），**不进 QML / SliceWorkspace**。
- 外部预览适配器（beatoraja/raindrop）→ M10+。

### M7.6 `#WAV` 占用查询

- core 查询命令：哪个 wav 被哪些 note/谱面引用、冲突、缺失。
- 项目面板/采样面板展示；**不进 SliceWorkspace**（保持单谱切音职责边界）。

## 5. UI 落点

- **项目面板**（左 dock 或独立页）：谱面表 + 资源表 + 操作按钮。
- **对比视图**：统计卡片 + 叠加时间轴 + A/B 切换。
- **顶部多文档标签条**（`doc/08` surface 已规划）。
- 新 QML 文件必须加入 `app/CMakeLists.txt` 的 `QML_FILES` 显式列表。

## 6. 关键决策（需拍板）

1. **Project 不合并文档**——保证 undo/保存语义不变。
2. 多谱面关系先按“文件 + 头部 DIFFICULTY/PLAYLEVEL”归类，不做数据库/难度变体元数据。
3. 对比**只读**；要改就在对应标签页改。
4. 批量先做安全项；破坏性操作最后且有 `dry_run`。
5. 打包提供可选“严格模式”（引用/大小写/编码全过才允许打包）。
6. 大包性能：先头部扫描，统计后台补。

## 7. 验收基线

- core：`project.scan/verify/compare/batch/pack` 单测，不依赖 `local/`。
- GUI 冒烟：打开文件夹 → 列谱面 → 开多个 → 对比 → 批量 → 打包，出截图。
- 完成后同步 `doc/04` §6 状态与 §7 里程碑表。

## 8. 开放问题

- 一首歌的“项目”边界：仅单层文件夹，还是递归（BMS 大包/多曲合集）？
- 对比是否要支持“同谱不同版本”（文件历史 / 改前改后 diff）？
- 打包是否附带 README/许可证模板？
- 批量操作是否包含 note 变换类（风险较高，倾向不做或严格预览）？
