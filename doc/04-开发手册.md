## 1. 项目一句话

BMS 谱面编辑器（替代 BMSE/iBMSC）。C++20 + Qt 6（**GUI 层 Qt Quick/QML**，core 零 Qt 依赖）+ CMake；Phase B 引入 PortAudio。许可 **GPL-3.0**（每个新文件加 SPDX 头 `// SPDX-License-Identifier: GPL-3.0-only`）。GUI 栈决策见 **doc/08**（2026-08 定：QML + 分层皮肤系统）。

## 2. 已定决策速查

- 平台：Windows 优先；架构保持跨平台（不引入 Win 专有 API 进 core）。
- 格式：**v1 只做 .bms 文本**（零第三方依赖手写解析）；bmson 仅架构预留（codec 接口先立）。
- 现行范围（M1–M6）：谱面信息 + 文件绑定 + note 摆放（含 LN/地雷/变速/undo）+ 随时播放 + 切音工作台。**不含**完整试玩（判定/计分；可选/外置）。
- 优先级：基础功能 → 编辑期间随时播放（M5，已完成）→ 切音工作台（M6，已完成）；试玩模式 = 可选/外置。
- 核心模型**格式无关**：无通道号、无 36 进制 ID、无 1296 上限——全是 bms codec 层的映射（02 §4）。
- 调用架构：**命令对象 = 唯一操作面**（`core/include/beatbench/core/command/`，命名空间 `beatbench::cmd`），GUI/CLI/未来 Lua 三种执行器共用（02 §6.1）。
- ✅ `core/include/beatbench/core/commands/`（**复数**、`beatbench::commands`）是 M0 骨架遗留的旧命令头（`apply`/`invert`/`merge_with` 接口）：0.3.0 核实**全仓库无 include、CMake 未列入、无任何调用方**，已在 0.3.0 后清理**删除**。现行框架只有 `core/command/`（**单数**），不要照旧笔记找复数目录。
- GUI 栈：**Qt Quick/QML + 分层皮肤系统**（2026-08 定，doc/08）；core 零 Qt 依赖不变。
- 采样：wav/ogg，44100/48000Hz 优先（M4 起有解码）。

## 4. 构建与测试

工具链要求：**C++20**——MSVC ≥ 19.29（VS 2022+）或 GCC ≥ 10 / Clang ≥ 12。
⚠️ Git for Windows 自带的 g++ 6.3 太老（不支持 C++20），不可用。
GUI 需要 **Qt 6.11+**（CI 验证版本 6.11.2；发布包内嵌 6.11.1）。

```bash
# CLI + 测试（Linux/macOS 单配置；测试需联网拉 GoogleTest）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure

# 只编 CLI（无网可用）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=OFF
cmake --build build --target beatbench-cli

# GUI（Linux/macOS；Qt 6.11+ via aqt/发行版包，QT_PREFIX 换成你的安装位置）
cmake -S . -B build-gui -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH="$QT_PREFIX" \
  -DBEATBENCH_BUILD_TESTS=OFF
cmake --build build-gui --parallel
# macOS 产物为 .app 包；运行需 QML2_IMPORT_PATH=build-gui/app（见下方「跨平台与 CI」）
```

```powershell
# Windows：MSVC（无 Qt 时 app 自动跳过；CI windows-msvc-core 同款）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=ON
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure

# Windows GUI：MinGW + Qt 6.11+（路径换成你自己的）
export QT_PREFIX=/c/Qt/6.11.1/mingw_64
export MINGW_BIN=/c/Qt/Tools/mingw1310_64/bin
cmake -S . -B build-gui -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_PREFIX_PATH="$QT_PREFIX" \
  -DCMAKE_CXX_COMPILER="$MINGW_BIN/g++.exe" \
  -DCMAKE_MAKE_PROGRAM="$MINGW_BIN/ninja.exe" \
  -DBEATBENCH_BUILD_TESTS=OFF
cmake --build build-gui --target beatbench
# 产物 build-gui/app/beatbench.exe；"$QT_PREFIX/bin/windeployqt.exe" --qmldir app/qml 部署 DLL（QML 必需）
```

**跨平台与 CI**（2026-09 起）：`.github/workflows/ci.yml` 五 job 钉住三平台——
`linux-core` / `windows-msvc-core`（无 Qt：core/cli/audio/tests）、`linux-full` /
`macos-full`（全量 + GUI 无头冒烟；macOS 为非阻塞门禁，summary job 会翻出其实际
结论）、`windows-mingw-full`（MinGW 全量 = 发布链路）。触发：push（master）+
PR（目标 master）+ 手动 dispatch。CMake 4 无需旗标：根 CMakeLists 已钳
`CMAKE_POLICY_VERSION_MINIMUM=3.5`（PortAudio v19.7.0 自声明 2.8）。

**当前边界**：① macOS `.app` 内不含 `BeatBench/` QML 模块目录，双击起不来
（需 `QML2_IMPORT_PATH` 指向构建树，模块入包属 macOS 打包范畴）；② GUI 交互
（悬停/拖拽）未人工验证（CI 只做无头冒烟）；③ PortAudio 实时输出未人工验证。

注意：
- **测试耗时分档**（2026-08）：完整回归 ≈ 2.5~5 分钟——大头 = 真实谱面时序/往返测试
  （`local/chart` 真实谱面集，缺失自动跳过）。日常用**快速回归**：
  `BB_SKIP_REAL=1 ./build/tests/Debug/beatbench_tests.exe`（<1s）；提交前跑完整回归；
  `BB_ONLY=<子串>` 只跑匹配文件名的样本（现象定位用）。
- 源文件一律 UTF-8 保存；CMake 已为 MSVC 加 `/utf-8`，不要移除；
- MinGW 路线用 MinGW-w64（不是 Git 自带 g++），生成器 `-G "MinGW Makefiles"`。
- 改动涉及音频/渲染时另跑：`cmake --build build --config Debug --target chart_renderer_test sample_cache_test audio_test`。
- GUI/桥层单测需带 Qt 的构建（`build-uitest`）：`ui_action_registry_test`、`theme_manager_test`、`slice_workspace_test`、`command_dispatcher_test`。MSVC `build/` 无 Qt 时这些目标自动跳过。
- ⚠️ **「无 Qt」≠「无网/可离线」**：`audio/CMakeLists.txt` 无条件 `FetchContent` 拉 PortAudio v19.7.0，
  离线干净构建需 `-DFETCHCONTENT_SOURCE_DIR_PORTAUDIO=<已有源码>`（googletest 同理），
  **复用下载源码时须如实标注**。PortAudio 以 C 语言子项目嵌入，靠根项目
  `project(... LANGUAGES C CXX)` 提供 C 语言（2026-09 起不再用 PowerShell 补丁脚本，见根 CMakeLists 注释）。
  跨平台以 CI 为准：三平台「编译 + 单测 + GUI 无头冒烟」由 ci.yml 钉住；
  PortAudio 实时输出（声卡路径）未做人工跨平台验证——CI 无声卡。

## 5. 代码约定

- 文件 snake_case（`bms_codec.cpp`）、类型 PascalCase（`TimingEngine`）、命名空间 `beatbench::<模块>`。
- 注释用中文（面向本项目维护者与后续小模型）；SPDX 头必须。
- core/audio 零 Qt/播放器依赖；事件容器保持按 (measure, pos) 升序。
- 提交信息：Conventional Commits 简版（`feat:`/`fix:`/`docs:`/`refactor:`/`test:`）。
- **只提交 doc/ 与源码；local/、build/ 永不上传。**
- ⚠️ **QML 字符串格式化只用链式单参 `.arg()`**（multi-arg 抛 `String.arg(): Invalid arguments`
  并中止当前 JS 函数）。
- ⚠️ **QML 双语言纪律**：逻辑放 C++（`app/bridge`），QML 只管表现与 `invoke`。新增业务不要往
  `SessionController.qml` / `Main.qml` 堆 JS；handler 用字符串方法名只是迁移期兼容，新动作优先
  在 C++ 注册真实处理器。
- ⚠️ **互斥单选组用「外部激活态」**：状态放 window/model 单值 + `active: 状态 === id`，
  不用控件 `checkable` 自翻（会断开绑定、多选残留）。
- ⚠️ **AUTOMOC 对 target sources 的自动 include 扫描不可靠**：带 Q_OBJECT 的 app 头文件
  必须显式列入 `add_executable(...)`。
- **用户偏好持久化**（Windows 默认 NativeFormat = 注册表）：`HKCU\Software\BeAtBench\BeAtBench\`
  —— `keymap/<动作id>` 用户快捷键；`audio/deviceIndex|sampleRate|framesPerBuffer|masterVolume`
  音频设置。皮肤、窗口几何、最近文件、编辑器偏好**尚未**持久化。Linux/macOS 为
  `~/.config/BeAtBench/BeAtBench.conf`。首选项「快捷键」页显示该路径，可复制或「打开配置位置」
  （Windows 导出 `%AppConfig%/BeAtBench-keymap.reg` 便于迁移）。崩溃诊断写工作目录
  `beatbench-crash.txt`；QML 告警写 `beatbench-qml-errors.log`。谱面 `.bak` / 自动保存走
  `EditorSession` 持久化钩子（与偏好无关）。
- **⚠️ 防回退/踩坑细节（BMS 通道保真、LN/LNTYPE 语义、共享 id、Windows 宽字符路径、
  miniaudio/PortAudio 三坑、SampleCache 引用协议、回调线程零分配等）→
  `local/doc/04-开发手册-完整版.md §5`**——改动相关代码前先读，每条来自真实踩坑。

### 已知限制（一句话）

- **#RANDOM/#IF 块内容编辑**：块内数据行/头部字段的往返不正确（编辑模型 = 非块内容 + raw 兜底）；
  播放/时序链路走 `expand_variants`，不受影响。修复需要 parser 控制块感知（中等偏上），按需立项——
  细节见 local/doc/04-完整版 §6。
- **.pms 另存为 .bms** 会按 sp/dp 重解释（跨扩展名另存属已知边界，产品不承诺）。
- **切音工作台（M6.4 现状）**：① 切音页有独立撤销栈（切片表/启用开关/手动点，最多 64 步）；
  切音页 Ctrl+Z/Y（无文本焦点）撤切音工作区，不碰谱面。文本框内仍撤文本。
  ② 变速谱网格/行换算用**单一 BPM**（行宽/拍线按当前 BPM 均分，变速处会漂）；
  ③ AA 起始 id 崩溃**未复现**（埋点已就位：`beatbench-crash.txt` + 导出步骤日志，再犯可定位）。
  ④ woslicer 式键盘已做：空格/←→/↑↓/Z/C/V/B + Ctrl+G/Shift+G/E/I/M，走 UiActionRegistry。
  ⑤ 切音工作区未导出切片**不**并入谱面脏标记（关闭/新建/打开只确认谱面+元信息草稿）。
