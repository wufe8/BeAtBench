# BeAtBench 开发手册（新会话引导）

> **给新会话/小模型的引导文档**：读完本文件即可开工，无需重读全部设计文档。
> 权威设计细节见 [02-对齐稿](./02-C++Qt方案对比与切音工作流.md)；本文件与其冲突时以 02 为准（并请顺手更新本文件）。

## 1. 项目一句话

BMS 谱面编辑器（替代 BMSE/iBMSC）。C++20 + Qt 6.8 LTS（Widgets）+ CMake + vcpkg；Phase B 引入 PortAudio。许可 **GPL-3.0**（每个新文件加 SPDX 头 `// SPDX-License-Identifier: GPL-3.0-only`）。

## 2. 已定决策速查

- 平台：Windows 优先；架构保持跨平台（不引入 Win 专有 API 进 core）。
- 格式：**v1 只做 .bms 文本**（零第三方依赖手写解析）；bmson 仅架构预留（codec 接口先立）。
- v1 范围：谱面信息 + 文件绑定 + note 摆放（含 LN/地雷/变速编辑/多模式视图/undo/自动保存）。**不含**试玩与实时播放（Phase B）、切音工作台（Phase C）。
- 优先级：基础功能 → 编辑期间随时播放（M5）→ 切音工作台（M6）；试玩模式=可选/外置。
- 核心模型**格式无关**：无通道号、无 36 进制 ID、无 1296 上限——这些全是 bms codec 层的映射（02 §4）。
- 调用架构：**命令对象 = 唯一操作面**（core/commands），GUI/CLI/未来 Lua 三种执行器共用（02 §6.1）。
- 采样：wav/ogg，44100/48000Hz 优先（Phase B 才需要解码）。

## 3. 仓库布局

```

```

## 4. 构建与测试

工具链要求：**C++20**——MSVC ≥ 19.29（VS 2022+）或 GCC ≥ 10 / Clang ≥ 12。
⚠️ Git for Windows 自带的 g++ 6.3 太老（不支持 C++20），不可用。本机已验证可用：MSVC BuildTools（VS 18）。

```powershell
# CLI + 测试（MSVC 默认生成器；测试需联网拉 GoogleTest）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=ON
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure

# 只编 CLI（无网可用）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=OFF
cmake --build build --config Debug --target beatbench-cli

# GUI：需 Qt 6.8 LTS（官方安装器 MSVC/MinGW 套件或 vcpkg），加 -DCMAKE_PREFIX_PATH=<Qt路径>
```

注意事项：
- 源文件一律 UTF-8 保存；CMake 已为 MSVC 加 `/utf-8`，不要移除；
- MinGW 路线用 MinGW-w64（不是 Git 自带 g++），生成器 `-G "MinGW Makefiles"`。

## 5. 代码约定

- 文件 snake_case（`bms_codec.cpp`）、类型 PascalCase（`TimingEngine`）、命名空间 `beatbench::<模块>`。
- 注释用中文（面向本项目维护者与后续小模型）；SPDX 头必须。
- core 零 Qt/音频依赖；当前 header-only，需要实现时转 STATIC 库。
- 事件容器保持按 (measure, pos) 升序；Note.ln_pair 存容器下标（编辑后需重算，M2 注意）。
- 提交信息：Conventional Commits 简版（`feat:`/`fix:`/`docs:`/`refactor:`/`test:`）。
- **只提交 doc/ 与源码；local/、build/ 永不上传。**

## 6. 当前状态与下一步（M1 任务清单）

状态：M0 骨架已提交（模型头文件 + CLI + 测试 + 文档）。**M1 格式层已完成并验证**：

### ✅ 已落地（2026-08，M1：文件读写 + 头部字段 + note 事件化 + CLI）

- `core/src/bms/`：BMS codec 实现
  - `bms_parser.cpp`：`read_bms/read_bms_file`——大小写不敏感 tag、`//`/`/* */`/`*` 注释、
    头部字段（已知/未知透传）、四类定义表（WAV/BMP/BPM/STOP，**独立命名空间**
    `#BPM01` 与 `#BMP01` 可共存，模型键 = (kind, id)）、3 位 id 变体原样保留、
    **数据行事件化**（槽位 → `Rational(i, N)`）、`#RANDOM/#IF/#SWITCH` 控制指令进
    `Chart.raw_lines` 保序保真、Diagnostic 诊断；
  - `bms_writer.cpp`：`write_bms`——头部规范顺序 + 定义表分组（id 升序）+ 事件重建
    数据行（通道聚合 + 槽位 LCM 最小化 + 同 pos 冲突自动分裂多行）+ raw 原样、
    BPM/STOP 事件写回 **#BPMxx/#STOPxx 定宽引用**（复用现有定义，缺则派生）、
    `#ENCODING` 声明按写出编码规范化、UTF-8/SJIS 双输出；
  - `channel_map.cpp` + `ChannelMap.hpp`：**通道字符串 → 格式无关语义/Lane 的纯映射表**
    （`bms_channel_rule` 正向 + `bms_channel_for` 反向；11-19/21-29/51-69/D-E 按
    beatoraja 共识；未知通道 KeepRaw；**换格式 = 换映射表**，解析逻辑不变）；
  - `encoding.cpp` + `sjis_table.hpp`（`tools/gen_sjis_table.ps1` 生成，三平台一致）：
    BOM / `#ENCODING` / 严格 UTF-8 校验启发式检测；CP932 双射映射（无效序列 → U+FFFD）；
  - `BmsUtil.hpp`：`c36_to_u32/u32_to_c36`（36 进制工具）。
- 解析规则要点（真实谱面验证）：
  - ch02 节拍 = 整段数值（含小数 `0.5`/`1.30208333333333`）；ch03 **偶数长度 = 槽位
    引用、奇数长度 = 整段直接数值**（Doppelganger 式 `0065536`/`8C`）；ch08/09 = 槽位引用；
  - LN 配对：同 lane「最近未配对头」匹配尾；LNTYPE 1 全尾 / LNTYPE 2 仅 `#LNOBJ` 值；
  - 事件容器顺序约定 = (measure, pos) 升序，同 pos 顺序未定义（对比时按
    (measure,pos,value) 规范化）。
- `cli/`：`info <file>`（元信息/定义表/**事件统计**/通道分布/诊断）与 `check <file>`
  （解析诊断 + 缺失 WAV 引用检查，退出码）。
- `tests/bms_codec_test.cpp`：43 个测试——合成解析/事件化/LN 配对/往返/编码 +
  **local/chart 全部真实谱面往返无损**（358 个，含 Doppelganger 变速谱、DP 谱、
  yukkuri 长小数节拍；缺失时跳过；`BB_ONLY=<子串>` 环境变量可单跑调试）；
  与旧解析器（local/bms）在 chart.txt 上逐通道物件数对照一致（113597 物件）。
