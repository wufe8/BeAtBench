## 1. 项目一句话

BMS 谱面编辑器（替代 BMSE/iBMSC）。C++20 + Qt 6（**GUI 层 Qt Quick/QML**，core 零 Qt 依赖）+ CMake；Phase B 引入 PortAudio。许可 **GPL-3.0**（每个新文件加 SPDX 头 `// SPDX-License-Identifier: GPL-3.0-only`）。GUI 栈决策见 **doc/08**（2026-08 定：QML + 分层皮肤系统）。

## 2. 已定决策速查

- 平台：Windows 优先；架构保持跨平台（不引入 Win 专有 API 进 core）。
- 格式：**v1 只做 .bms 文本**（零第三方依赖手写解析）；bmson 仅架构预留（codec 接口先立）。
- v1 范围：谱面信息 + 文件绑定 + note 摆放（含 LN/地雷/变速编辑/多模式视图/undo/自动保存）。**不含**试玩与实时播放（Phase B）、切音工作台（Phase C）。
- 优先级：基础功能 → 编辑期间随时播放（M5）→ 切音工作台（M6）；试玩模式 = 可选/外置。
- 核心模型**格式无关**：无通道号、无 36 进制 ID、无 1296 上限——全是 bms codec 层的映射（02 §4）。
- 调用架构：**命令对象 = 唯一操作面**（core/commands），GUI/CLI/未来 Lua 三种执行器共用（02 §6.1）。
- GUI 栈：**Qt Quick/QML + 分层皮肤系统**（2026-08 定，doc/08）；core 零 Qt 依赖不变。
- 采样：wav/ogg，44100/48000Hz 优先（M4 起有解码）。

## 4. 构建与测试

工具链要求：**C++20**——MSVC ≥ 19.29（VS 2022+）或 GCC ≥ 10 / Clang ≥ 12。
⚠️ Git for Windows 自带的 g++ 6.3 太老（不支持 C++20），不可用。本机已验证可用：MSVC BuildTools。

```powershell
# CLI + 测试（MSVC 默认生成器；测试需联网拉 GoogleTest）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=ON
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure

# 只编 CLI（无网可用）
cmake -S . -B build -DBEATBENCH_BUILD_TESTS=OFF
cmake --build build --config Debug --target beatbench-cli

# GUI：Qt Quick/QML，需 Qt 6 + Quick/QuickControls2（本机 6.11.1 MinGW，命令见 doc/07 §2）
```

注意：
- **测试耗时分档**（2026-08）：完整回归 ≈ 2.5~5 分钟——大头 = 真实谱面时序/往返测试
  （`local/chart` 真实谱面集，缺失自动跳过）。日常用**快速回归**：
  `BB_SKIP_REAL=1 ./build/tests/Debug/beatbench_tests.exe`（<1s）；提交前跑完整回归；
  `BB_ONLY=<子串>` 只跑匹配文件名的样本（现象定位用）。
- 源文件一律 UTF-8 保存；CMake 已为 MSVC 加 `/utf-8`，不要移除；
- MinGW 路线用 MinGW-w64（不是 Git 自带 g++），生成器 `-G "MinGW Makefiles"`。
- 改动涉及音频/渲染时另跑：`cmake --build build --config Debug --target chart_renderer_test sample_cache_test audio_test`。
- GUI 单测需 AUTOMOC：`ui_action_registry_test`、`theme_manager_test`（随构建配置，MSVC 侧）。

## 5. 代码约定

- 文件 snake_case（`bms_codec.cpp`）、类型 PascalCase（`TimingEngine`）、命名空间 `beatbench::<模块>`。
- 注释用中文（面向本项目维护者与后续小模型）；SPDX 头必须。
- core/audio 零 Qt/播放器依赖；事件容器保持按 (measure, pos) 升序。
- 提交信息：Conventional Commits 简版（`feat:`/`fix:`/`docs:`/`refactor:`/`test:`）。
- **只提交 doc/ 与源码；local/、build/ 永不上传。**
- ⚠️ **QML 字符串格式化只用链式单参 `.arg()`**（multi-arg 抛 `String.arg(): Invalid arguments`
  并中止当前 JS 函数）。
- ⚠️ **QML 双语言纪律**：逻辑放 C++（app/bridge），QML 只管表现，JS 不写散。
- ⚠️ **互斥单选组用「外部激活态」**：状态放 window/model 单值 + `active: 状态 === id`，
  不用控件 `checkable` 自翻（会断开绑定、多选残留）。
- ⚠️ **AUTOMOC 对 target sources 的自动 include 扫描不可靠**：带 Q_OBJECT 的 app 头文件
  必须显式列入 `add_executable(...)`。
- **⚠️ 防回退/踩坑细节（BMS 通道保真、LN/LNTYPE 语义、共享 id、Windows 宽字符路径、
  miniaudio/PortAudio 三坑、SampleCache 引用协议、回调线程零分配等）→
  `local/doc/04-开发手册-完整版.md §5`**——改动相关代码前先读，每条来自真实踩坑。

        measureAt(0)/measureAt(h)；cursorPosition 负拍位夹 0。⚠️ 0→1 小节边界仍有谱面固有跳变
        （9999xxx 使 0 小节近零时长，播放头快速越过）——非锁定问题。
        🔄 **A/B 标记扣留白 + 滚动上限（2026-09 用户二连）**：① A 点曾显示在实际位置前 1-2 小节——
        `PlayheadOverlayItem.yForSec` 未扣 `m_leadMeasures`，A/B 标记比实际低(早) 2 小节；加
        `leadMeasures` 属性（与 ChartView 同源）后用 `(mf+lead)*mh`（与 `yOf` 同构）。② 从**底部**起播
        仍跳变——手动滚动能滚进留白区（红线读负拍位、起播夹 0），follow 再从留白对齐到「小节0@90%」
        而跳；`maxScrollY()` 把 topHigh 滚动上限封到「小节 0 落播放线(90%)」（=scrollToStart 对齐位），
        手动滚动不进入留白区；setScrollY/clampScroll/followPlayheadTick/scrollToStart 统一用它，
        滚动条 `maxY` 用 `view.maxScrollY`。
        🔄 **播放/循环点与红线统一（2026-09）**：Space 起播起点 = 循环 A（若设）否则**红线/视口光标**
        （`togglePlayback` 改为 `seek 红线/A → play`，`AudioEngine.togglePlay` 不再用于起播）；A/B 循环点
        由 **红线位置** 打点（`setLoopA/B(sec)`，QML 传 `editPage.cursorSec`），不再用播放时钟 `positionSec`
        （用户反馈：暂停+滚动后 A/B 打点错位、Space 跳回旧位置）；循环 A→B 绕回 A；**只设 B（无 A）→ 播放到 B 即暂停**。

### 已知限制（一句话）

- **#RANDOM/#IF 块内容编辑**：块内数据行/头部字段的往返不正确（编辑模型 = 非块内容 + raw 兜底）；
  播放/时序链路走 `expand_variants`，不受影响。修复需要 parser 控制块感知（中等偏上），按需立项——
  细节见 local/doc/04-完整版 §6。
- **.pms 另存为 .bms** 会按 sp/dp 重解释（跨扩展名另存属已知边界，产品不承诺）。
