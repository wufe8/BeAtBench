# BeAtBench 文档地图（按需读取）

> **目的**：让新会话/协作者只读当前任务需要的文档，不整包通读。
> **判据（决定 `doc/` 还是 `local/doc/`）**：这份文档是**交接对象**——一个没参与本项目的协作者/新会话
> 只读它就能正确完成相应工作？→ 是则放 **`doc/`**（提交进仓库）；它只是**过程痕迹**——会话记录/进度/
> 踩坑/待拍板/被取代草稿/本机笔记，需要背景或易过时？→ 放 **`local/doc/`**（gitignore，永不提交）。
> **`local/` 为本机私人笔记、样本谱面与工具生成物；仓库内不得依赖、不得提交。**
> **doc/04 是简版现状手册**；开发历史/踩坑/防回退细节（与开发会话强耦合）在 `local/doc/04-开发手册-完整版.md`（gitignore）。

## 3. 文件分布约定（doc vs local/doc）——防误放

> **唯一判据**：① 能被"非本项目参与者"独立理解并用来工作 → `doc/`；② 只有越过会话背景才看得懂 / 一过时就没用 / 是需要拍板的讨论或已被取代的草稿 → `local/doc/`。

| 类别 | 去向 | 例 |
|---|---|---|
| 权威/现状/规格/设计稿/事实参考 | **`doc/`**（提交） | 02 对齐稿、04 简版手册、05 界面设计、06 协议规格、08 QML/皮肤、09 操作注册、01 调研、BMS 笔记 |
| 项目门面 | **`doc/`**（提交） | 根 `README.md`、`CHANGELOG.md` |
| 开发进度/踩坑/防回退 | **`local/doc/`** | `04-开发手册-完整版.md` |
| 老里程碑计划/进度流水 | **`local/doc/`** | `07-M2开发准备计划.md` |
| 已被取代的草稿/定案讨论 | **`local/doc/`** | `03-技术栈全景对比`、`10-主题与皮肤路线`、`11-L2皮肤布局` |
| 工具生成物/报告/图 | **`local/`**（子目录，如 `archify/`） | 架构图 HTML/JSON、视觉检查图 |
| 本机私人笔记/样本/测试素材 | **`local/`**（gitignore 忽略二进制） | 样本谱面、截图、音频 |
| 会话讨论/待拍板（未落定） | **`local/doc/`** | 需拍板的设计取舍 |

> **防再犯纪律**：写完临时笔记/进度/踩坑/报告后，先按上面判据归位；**只有"交接对象"才往 `doc/` 写**。老会话的对话记录、调试流水、截图、生成物一律 `local/`。若不确定放哪，先放 `local/doc/` 并标注待升格，别直接进 `doc/`。

## 4. 建议读取顺序

1. `doc/04-开发手册.md`（引导）；
2. 按上表查当前任务对应的文档；
3. 需要设计细节时翻 `doc/02` 对应章节；
4. **不要整包通读** 01 / 03 / 05（它们是背景与草案，非当前事实）。
